# 文档入库隐私脱敏

## 背景与目标

- 背景：当前解析文本在进入切块、元数据提取和检索索引前没有统一隐私脱敏。
- 目标：用本地自托管 Presidio Analyzer 识别首版结构化隐私信息，并在入库前不可逆替换。
- 成功标准：隐私值不进入 RAG 索引、Hypothetical Questions 或 Obsidian 来源正文；含隐私或本地预检不完整的解析结果不发送给 MinerU 云端。

## 范围

- 包含：手机号、校验有效的 18 位居民身份证号、Luhn 有效的银行卡号、邮箱及明显凭据；文档正文、解析块、标题、文件名、业务字符串元数据和 Obsidian 元数据。
- 包含：MinerU 云调用前的本地解析与隐私预检；预检不完整、发现隐私或本地分析器不可用时不调用云端。
- 不包含：姓名/地址猜测、历史索引回填、原始文件字节脱敏、其他 OCR/ASR/Vision 服务的出站控制。

## 验收标准

### AC-01：入库文本脱敏

- 有效结构化隐私和明显凭据在分块、Embedding、检索索引与 Obsidian 来源正文前替换为类型标签。
- 分析器不可用、响应错误或输入超限时，入库失败关闭；日志不包含匹配原文。
- 验证方式：隐私服务定向单测、入库编排测试、build 和 lint。

### AC-02：MinerU 出站门禁

- 只有本地解析完整、无识别隐私、且没有未 OCR 图像时才调用 MinerU 云端。
- 发现隐私时使用已脱敏本地解析结果；预检不完整时使用可用本地结果并标记 partial；本地解析不可用则失败。
- 验证方式：控制器定向单测/mock，证明门禁分支不会调用云服务。

### AC-03：本地服务可手动运行

- Presidio 通过 Docker `privacy` profile 手动启动并只绑定 loopback；`pnpm run dev:backend` 不启动该服务。
- 验证方式：Docker Compose 静态配置检查及操作文档核对。

## 边界与约束

- 原始文件字节继续按既有流程保留；本功能不声称静态存储中的原件已脱敏。
- 首版使用中文结构化规则，不自动识别姓名和地址；图像 OCR、音频 ASR、视频 Vision 等其他外部 Provider 不在此门禁范围。
- 不新增 Node 依赖；RAG API 通过本机 loopback HTTP 调用 Presidio。
- 现有工作区含未提交修改，实施只修改本规格和方案列出的目标文件。
