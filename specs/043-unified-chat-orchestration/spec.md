# 统一 Chat 编排与三模式收敛

## 背景与目标

- 背景：HTTP、SSE、AG-UI 分别准备上下文、调用 Agentic 与保存结果；显式 Simple 在特定意图下仍进入 Agentic 入口，流式正文也可能先于最终引用校验发布。
- 目标：所有 Chat 入口共用 `ChatService` 的请求编排、执行边界、结果校验与持久化；保留 Simple、Auto、Agentic 三个产品选项，内部只保留 Simple 与 Agentic 两个执行引擎。
- 成功标准：同一请求只分类一次；Simple 永不进入 Agentic；Auto 升级复用已有证据；HTTP、SSE、AG-UI 对结果保存与最终正文发布采用同一契约。

## 范围

- 包含：ChatService 公共执行入口；HTTP SSE 与 AG-UI 改为适配层；Simple 固定线性边界；事件缓冲后的正式正文发布；对应单元测试和功能步骤文档。
- 不包含：数据库 schema／迁移、Task Agentic 业务编排、外部工具新增、跨请求缓存、Obsidian／Bad Case 既有 ACL 数据模型改造。

## 用户与行为

### AC-01：显式 Simple 保持线性执行

- 前置条件：用户指定 `simple`，即使问题被识别为多问题、公共事实或多义。
- 操作：通过 HTTP、SSE 或 AG-UI 发起提问。
- 预期结果：不调用 `AgenticRagService.run`，不拆子问题、不进入反思／工具循环；仅允许固定的线性取证、最多一次允许的网页补证、生成与引用校验。
- 验证方式：ChatService、流式入口定向单测。

### AC-02：所有 Chat 入口使用一次请求语义

- 前置条件：用户从普通 HTTP、SSE 或 AG-UI 入口提问。
- 操作：执行任一模式。
- 预期结果：上下文、意图、来源策略、权限范围和图谱计划只准备一次并传入执行引擎；下游不重复分类，也不放宽来源限制。
- 验证方式：公共编排单测与 Agentic 参数断言。

### AC-03：Auto 与 Agentic 复用证据，图谱／Obsidian 不重复读取

- 前置条件：Auto 或 Agentic 请求已有 Fast Path 证据。
- 操作：Auto 选择 Simple，或升级 Agentic。
- 预期结果：正式生成复用同一 `prefetchedFastPath`；Obsidian 只格式化已命中内容；图谱仅由 `requiresGraph` 计划触发，原问题不会被子问题重复查询。
- 验证方式：Karpathy、Agentic 定向单测。

### AC-04：流式正文与最终校验结果一致

- 前置条件：依赖引用的 RAG 回答通过 SSE 或 AG-UI 返回。
- 操作：引擎产生 token、引用和最终结果。
- 预期结果：路由、检索与工具进度可以实时发送；正式正文仅在最终结果确定后发送，页面看到的内容、会话记录、Query Log 与最终引用一致。
- 验证方式：流式事件顺序与持久化单测。

### AC-05：统一保存与审计

- 前置条件：任一入口成功完成问答。
- 操作：提交请求并等待结束。
- 预期结果：会话消息、短期记忆、Mem0、历史向量、Query Log、Run／Trace 使用同一 ChatResult；不会由入口各自重复写入。
- 验证方式：入口单测与调用次数断言。

## 边界与约束

- 服务端与用户来源限制是上限；模型意图只能收紧，不能扩大。
- 流式缓冲会增加正式正文首字延迟，但不得为低延迟发布未经校验的正文。
- 现有 Task 审批／恢复和通用 Loop 恢复不在本变更范围内；不声称已经实现任意节点自动恢复。
- 保留现有模型选择、角色预设、插件白名单、Artifact 生成和 AG-UI 事件格式。
