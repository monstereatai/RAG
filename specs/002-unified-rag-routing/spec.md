# 统一 RAG 路由与面试口径定稿

## 背景与目标

- 背景：当前 Simple、Auto、Chat Agentic 与 Karpathy 在运行时和面试材料中存在职责重叠、超长问题路由和无证据模型兜底等冲突口径。
- 目标：统一为“精确直答 → 统一 Hybrid RAG → 按需 Agentic”，并使运行时、架构文档和活跃面试材料保持一致。
- 成功标准：三种模式只负责执行策略选择，共享同一检索底座；没有可靠本地或联网证据时明确拒答；面试材料只保留一套权威流程。

## 范围

- 包含：精确直答职责收紧、Simple 统一混合检索、Auto 前置直答与路由修正、Agentic 无证据处理、活跃面试材料定稿、相关测试和构建验证。
- 不包含：数据库 Schema／迁移、`.env`、管理后台页面、API 契约、索引删除、生产部署、Git 提交与类／目录大范围重命名。

## 用户与行为

### AC-01：统一执行架构

- 前置条件：用户选择 Simple、Auto 或 Chat Agentic。
- 操作：发起问答。
- 预期结果：三种模式遵循“精确直答 → 统一 Hybrid RAG → 按需 Agentic”，Karpathy 不再作为独立通用检索链路。
- 验证方式：代码路径检查、流程图和架构文档核对。

### AC-02：Simple 可靠回答

- 前置条件：存在或不存在受治理精确答案、本地证据和联网能力。
- 操作：使用 Simple 提问。
- 预期结果：精确答案可跳过 Hybrid；未命中后执行统一混合检索；本地与联网均无证据时明确拒答，不使用无引用模型兜底。
- 验证方式：KarpathyRagService 定向单测。

### AC-03：Auto 正确路由并复用证据

- 前置条件：问题可能精确、简单、复杂、超长或无本地索引。
- 操作：使用 Auto 提问。
- 预期结果：先尝试精确直答；未命中才执行 Fast Path；简单且证据充分走 Simple，复杂或证据不足走 Agentic；超长不再强制 Simple；Agentic 复用 Fast Path。
- 验证方式：AgenticRagService 定向单测。

### AC-04：Agentic 无证据安全收口

- 前置条件：本地没有可用证据。
- 操作：使用 Agentic 或由 Auto 升级。
- 预期结果：状态机仍可尝试 Web Search；本地与联网均无证据时返回明确拒答，不生成无引用项目结论。
- 验证方式：AgenticRagService 定向单测。

### AC-05：面试口径唯一且一致

- 前置条件：阅读活跃架构和面试材料。
- 操作：查看三种问答模式、Karpathy 和兜底策略。
- 预期结果：《功能步骤流程》为唯一流程真源；其他活跃材料与其一致；历史方案保留但不作为当前口径。
- 验证方式：全文术语检索、Mermaid 解析和人工 Diff 审阅。

### AC-06：兼容性和工程验证

- 前置条件：现有调用方继续使用原 API。
- 操作：运行相关单测、Lint 和 Build。
- 预期结果：API 请求／响应结构不变，旧直答参数保持兼容，定向测试与构建通过。
- 验证方式：自动化命令。

## 边界与约束

- 错误态／空态：无可靠证据时返回统一拒答文案和明确原因。
- 兼容性：保留 `KarpathyRagService` 类名及旧 `karpathyDirectAnswer` 参数兼容入口。
- 性能、安全、隐私：Auto 精确命中跳过 Hybrid；副作用工具审批策略不放宽；不记录敏感 Prompt。
- 现有项目规范：先更新规范文档，再修改运行时代码；只修改白名单文件。

## 待确认项与假设

- 已确认：不删除现有本地 BM25 索引；其定位改为精确直答／降级实现。
- 已确认：普通 Chat 默认不等待答案审批；保留显式 `enableInterrupt` 兼容能力。
- 已确认：本地与联网均无证据时拒答，不使用通用模型兜底。
