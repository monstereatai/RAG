# 高级 Agent 平台能力补齐

## 背景与目标

当前项目已经有 Agent Loop、LangGraph Checkpoint、审批恢复、评测脚本和观测采集，但这些能力还没有完全形成统一的生产闭环。目标是补齐四类能力，并用可重复的测试证明它们可用。

成功标准：运行可恢复，审批可追踪，三条检索链路可回归评测，运行指标和故障链路可查询。

## 范围

### 包含

- Agent Runtime 的运行记录、取消、重试、幂等、预算和恢复契约。
- Chat Agentic 与生产工作流的审批／驳回／局部重跑一致性。
- Simple、Auto、Agentic 三条链路的离线和真实接口评测门禁。
- HTTP、Agent Node、检索、工具、模型、审批和恢复事件的统一关联观测。
- PostgreSQL migration、评测门禁脚本、Prometheus／Grafana 配置模板及相关文档。

### 不包含

- 更换 NestJS、LangGraph、Milvus、PostgreSQL、Redis 或模型供应商。
- 自动写入生产密钥、生产部署、域名、证书或真实告警通知。
- 改变现有三条问答链路的业务定义。
- 将会话临时设定提升为公共知识库事实。

## 验收标准

### AC-01：Agent Runtime 可持久化和恢复

- 前置条件：创建一个带预算和工具调用的 Agent Run。
- 操作：查询运行状态，触发取消或失败，再执行重试／恢复。
- 预期结果：运行状态、预算、步骤、工具调用和失败原因可查询；成功副作用不会因重试重复执行。
- 验证方式：Runtime 单测、数据库集成测试、Redis Checkpoint 恢复测试。

### AC-02：审批恢复安全可控

- 前置条件：工作流进入 `pending_approval` 或 `revision_required`。
- 操作：批准、驳回、指定岗位局部重跑，并模拟未知副作用。
- 预期结果：批准继续执行，驳回只重跑指定岗位及下游；未知副作用不得自动盲目重放；所有动作有审计事件。
- 验证方式：工作流单测、恢复集成测试、故障注入测试。

### AC-03：三条检索链路具备质量门禁

- 前置条件：准备内部资料、公共事实、无资料问题、历史冲突和联网补证样本。
- 操作：以后台真实入口分别执行 Simple、Auto、Agentic。
- 预期结果：记录最终答案、路由、引用、检索状态、延迟和错误；任一链路低于阈值时评测失败。
- 验证方式：评测脚本、三模式接口回归测试、真实后台同等请求回放。

### AC-04：运行链路可观测

- 前置条件：执行一次问答、一次工具调用、一次审批恢复和一次失败重试。
- 操作：按 Trace ID、threadId、runId 查询运行中心和指标接口。
- 预期结果：HTTP、Agent Node、检索、工具、模型、审批和恢复事件能够关联；可查看延迟、错误、预算、引用和恢复结果。
- 验证方式：Tracing、Prometheus、Langfuse smoke、Runtime Event 和 Run Center 集成测试。

### AC-05：质量门禁可接入 CI

- 前置条件：代码、评测集和测试依赖已安装。
- 操作：执行质量门禁命令。
- 预期结果：构建、单测、三链路评测、恢复测试任一失败时退出非零；通过时生成结构化报告。
- 验证方式：本地命令和 CI 配置静态校验。

### AC-06：文档和进度与实现一致

- 预期结果：架构文档、功能步骤流程文档、ROADMAP 和验证记录不再把未实现能力写成已完成。
- 验证方式：链接校验、`git diff --check`、逐项对照代码和测试证据。

## 边界与约束

- 错误态：依赖不可用时必须安全降级并留下可查询原因，不得伪造成功。
- 幂等性：副作用工具必须使用幂等键和明确的 `completed／running／unknown` 状态。
- 权限：运行记录、证据和引用按用户／租户权限隔离。
- 性能：新增观测不得阻塞主问答链路；Langfuse 失败只记录告警。
- 数据：migration 必须可回滚，评测报告不得包含密钥和完整用户敏感原文。
