# 产研运工作流启动与流转可靠性

## 背景与目标

- 背景：2026-11-05 的审查指出工作流可能批准模型降级产物；启动请求没有稳定幂等键且 Run、任务和 Outbox 分开写入；审批通知没有可靠恢复边界；hierarchical 依赖批次仍由游标串行执行。
- 目标：确保质量失败不会越过岗位边界，启动与通知意图可恢复，并让 hierarchical 同层岗位并行且能按岗位恢复。
- 成功标准：下列 AC 均有自动化或明确的环境验证证据；旧检查点、审批、修订和取消语义保持可用。

## 范围

- 包含：P0-1 质量判定与模型重试；P0-2 `requestId`、原子启动、Outbox 重投和派发状态；P0-3 审批通知 Outbox；P1-1 依赖层并行；P1-2 启动表单与依赖/审批预览。
- 不包含：生产部署、真实钉钉群发、模型或检索服务更换、新依赖、数据库 schema 变更、无关工作流重构。

## 验收标准

### AC-01：质量门禁阻止降级结果自动批准

- 前置条件：岗位模型连续生成失败，或岗位产物存在未支持声明/质量不足。
- 操作：以默认 `approvalMode=auto` 启动工作流。
- 预期结果：工作流停在该岗位并给出可处理原因；下游岗位不启动；岗位任务为失败/待修订；产物保持未批准；运行记录显示原因。质量通过后才应用人工审批策略，正常结果仍遵从原策略。
- 验证方式：生产工作流定向单测覆盖生成失败、证据不足和正常 auto/required/risk_based 分支。

### AC-02：启动请求幂等且 Run、任务和派发意图原子提交

- 前置条件：管理端为一次启动操作生成稳定 `requestId`。
- 操作：并发提交同一 ID、超时后复用同一 ID，并模拟事务中途失败。
- 预期结果：同一租户/用户/ID 只返回一个 `threadId` 和一份计划；参数不同返回冲突；事务失败时 Run、任务和 Outbox 全部回滚；提交后即使进程退出或 Redis 暂不可用，Outbox 恢复后可派发。
- 验证方式：并发/事务回滚测试及 Outbox/BullMQ 恢复验证。

### AC-03：审批通知意图在检查点保存后可靠重试

- 前置条件：工作流到达人工审批状态。
- 操作：模拟状态保存前后 Worker 退出及通知服务暂时不可用。
- 预期结果：待审批入口持续存在；状态保存后 Outbox 可重试通知；重复执行只保留一个通知意图，其去重身份包含工作流、修订、批次与审批检查点。
- 验证方式：工作流检查点恢复、Outbox 幂等和通知失败重试测试；真实钉钉投递单独验收。

### AC-04：hierarchical 同层并行且只重跑失败岗位

- 前置条件：选中 design、backend、frontend 等存在依赖层的岗位。
- 操作：执行 hierarchical 工作流，并模拟同层一成一败及 Worker 强杀/BullMQ 重投。
- 预期结果：同层并行；依赖岗位等待整层质量检查通过；成功岗位的模型结果和产物复用，只重试失败岗位；sequential 和旧 `executeBatch` 检查点继续可运行。
- 验证方式：定向单测和跨 Worker 恢复验证；用可重复的延迟模型比较串行/并行耗时与估算 Token，不把 mock 结果当作真实模型成本。

### AC-05：启动表单突出常用输入并预览执行计划

- 前置条件：打开管理端“启动工作流”。
- 操作：选择项目、背景、岗位和审批策略。
- 预期结果：常用字段默认可见；最大步骤、插件、协作方式和风险阈值位于高级配置；启动前显示依赖层和预计审批条件；hierarchical 文案准确描述已实现的同层执行方式。
- 验证方式：管理端组件/服务测试、Biome、TypeScript 和 antd 检查。

### AC-06：启动状态和兼容流转可恢复

- 预期结果：前端能区分已受理、排队中、运行中和失败；超时后可查询或按原 `requestId` 重试；审批、修订、取消及旧检查点恢复没有回归。
- 验证方式：工作流 API/队列状态测试及对应定向回归。

### AC-07：并行效果有可复查数据

- 预期结果：记录串行与 hierarchical 模拟场景的耗时、模型调用次数和估算 Token；结果只说明该模拟场景，不推断生产流量或真实成本。
- 验证方式：同一 fixture、同一模型延迟和同一岗位输入的可重复比较。

## 边界与约束

- 新请求的唯一身份按 tenant、user、requestId 计算，并复用 Outbox 现有唯一索引；不增加迁移。
- 请求参数使用规范化摘要比对；同 ID 不同参数返回冲突。BullMQ 继续按稳定 job ID 去重。
- 模型重试仅覆盖可恢复模型调用错误；取消、权限错误、无效输入和工具/持久化错误不做无意义模型重试。
- 新并行执行使用 LangGraph 检查点能力保存岗位节点写入；旧版本检查点保留原路由。
- Outbox 与外部钉钉服务采用至少一次投递语义；稳定键保证通知意图去重，远端响应丢失时仍可能发生重复投递。
- 不修改 `.env`、密钥、CI/CD，不执行生产发布或真实通知。
- 项目验证以根目录 `CLAUDE.md`、`apps/admin-web/CLAUDE.md` 和子项目脚本为准。
