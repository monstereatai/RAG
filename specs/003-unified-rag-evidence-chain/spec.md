# 统一 RAG 证据链重构

## 背景与目标

- 背景：现有全文搜索、Karpathy RAG、Auto 与 Agentic RAG 分别构建候选、判断充分性和决定联网。它们对同一问题使用了不同的查询表达与门禁，造成「搜索能命中，问答却资料不足」「用户限定资料库仍可能走联网」「回答只回显片段」等不可接受的生成事故。
- 目标：让一次用户提问只形成一个可复用、可诊断的本地证据包；Simple、Auto 与 Agentic 仅在编排深度上不同，不再重建相互矛盾的充分性结论。
- 成功标准：本地证据已通过统一语义充分性门禁时，所有问答模式都生成带引用的回答；本地限定策略绝不调用联网工具；无证据时才安全降级。

## 范围

- 包含：后端 RAG 的共享证据模型、单一充分性判定、来源策略约束、Agentic 对预取证据的复用、引用优先回答降级、语义路由评测样本与回归测试。
- 不包含：变更数据库 Schema、向量库／Elasticsearch 索引结构、模型供应商、真实线上联网配置、前端视觉重做。

## 用户与行为

### AC-01：同一问题使用同一证据结论

- 前置条件：本地 Hybrid RAG 已为问题返回具备可用重排分的片段。
- 操作：以 Simple、Auto、Agentic 三种模式提交同一资料库问题。
- 预期结果：三种模式复用同一证据充分性结论；不得因 Agent 子问题改写而将已充分的原始证据降级为「资料不足」。
- 验证方式：Karpathy 与 Agentic 单测，覆盖「指令词不在资料原文但语义重排通过」的场景。

### AC-02：来源策略是强约束

- 前置条件：路由输出 `local_only`。
- 操作：提交本地知识库限定问题，且本地证据不足。
- 预期结果：不调用 Bocha／网页搜索，返回可操作的本地资料不足提示和真实诊断原因。
- 验证方式：Agentic 节点单测断言联网服务未被调用；路由评测断言不确定来源默认 `local_only`。

### AC-03：回答不是原始片段堆砌

- 前置条件：证据包充分且问题要求介绍、总结或多片段综合。
- 操作：提交实体总结类问题。
- 预期结果：优先得到完整的受引用约束回答；生成失败或引用不合格时，回退到结构化证据摘要，而不是直接展示无标签原片段。
- 验证方式：Karpathy／Agentic 单测验证引用校验与摘要降级。

### AC-04：路由不依赖业务关键词硬编码

- 前置条件：输入为未知实体、错别字实体或来源未明确的问题。
- 操作：执行语义路由评测集。
- 预期结果：由 LLM Few-shot＋结构化结果决定来源；解析失败或低置信度安全收敛到本地检索，评测样本覆盖本地、公共、实时和边界情形。
- 验证方式：`pnpm --dir backend eval:query-routing` 与路由单测。

### AC-05：全链路可诊断与可回归

- 前置条件：服务可启动且本地评测／测试环境可用。
- 操作：执行构建、定向单测、路由评测与 API smoke。
- 预期结果：每次响应能解释证据来源、充分性和是否跳过联网；自动化测试能阻止上述事故回归。
- 验证方式：Backend build、定向 Jest、评测脚本与本地 SSE 回放。

## 边界与约束

- 错误态／空态：模型评估失败时只能回退到同一证据包的确定性门禁；不得转为自由回答或静默联网。
- 兼容性：保持现有 SSE 事件、`RetrieveOptions` 和 API 响应字段兼容。
- 性能、安全、隐私：仅构建一次本地 Hybrid 证据包；`local_only` 不允许任何外网工具；所有引用维持权限与生命周期过滤。
- 现有项目规范：不改 `.env`、迁移、CI 或部署；不处理用户已有 `.obsidian/workspace.json`、`workspace/bm25-index.json` 运行时修改。

## 待确认项与假设

- 假设：现有 DashScope Rerank 分数可用时仍以当前 `RAG_MIN_RERANK_SCORE` 作为统一语义门槛；未配置重排时使用已有混合检索／词面兜底。
- 假设：用户「全都重构掉」及「用 Goal 模式重构」已批准本 Spec 和后续计划；不创建或切换受保护分支。
