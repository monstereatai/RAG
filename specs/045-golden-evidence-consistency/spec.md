# 业务黄金评测集与三链路证据一致性

## 背景与目标

- 背景：仓库已有脱敏业务样本，但没有统一覆盖内部业务问答、多轮上下文、冲突事实、引用、拒答／联网降级和三链路路由的黄金评测入口；Simple、Auto、Agentic 虽然共用 Hybrid RAG，但 Agentic 汇合候选时可能按 RRF 分覆盖 Rerank 顺序，生成兜底也存在重复实现。
- 目标：建立 50～100 条可审计的业务黄金评测集，并让三条链路共享同一套证据排序、引用校验和受约束生成策略。
- 成功标准：黄金集可离线校验且覆盖全部要求维度；三条链路对同一证据集使用一致的排序和引用门禁；新增回归测试能复现 RRF／Rerank 和引用失败场景。

## 范围

- 包含：黄金集清单与校验脚本；三链路证据排序统一；Agentic 复用统一证据生成／引用兜底；三链路专项测试；CI 门禁与验证文档。
- 不包含：引入新的检索数据库、修改现有数据库 schema、替换 Embedding／Rerank 厂商、把脱敏样本宣称为真实生产数据。

## 用户与行为

### AC-01：业务黄金评测集覆盖完整

- 前置条件：仓库可以读取脱敏业务样本和项目内部文档样本。
- 操作：运行黄金集校验命令。
- 预期结果：黄金集包含 50～100 条案例，且覆盖内部业务问答、多轮上下文、冲突事实、引用准确性、拒答／联网降级和 Simple／Auto／Agentic 路由维度；每条案例都有来源、期望策略和可验证断言。
- 验证方式：`npm run eval:golden-business`。

### AC-02：黄金集能作为三链路回放输入

- 前置条件：后端、鉴权和检索依赖可用。
- 操作：设置 `GOLDEN_EVAL_REQUIRE_LIVE=true` 执行黄金集入口回放。
- 预期结果：脚本使用同一个 `/api/v1/chat` 入口分别请求 Simple、Auto、Agentic，按模式、类别和引用／拒答／路由结果输出报告；服务或向量依赖不可用时明确标记阻塞，不伪报通过。
- 验证方式：`GOLDEN_EVAL_REQUIRE_LIVE=true npm run eval:golden-business`。

### AC-03：RRF 与 Rerank 排序在三链路一致

- 前置条件：同一查询返回带 `totalScore` 和可选 `rerankScore` 的候选片段。
- 操作：分别执行 Simple、Auto 升级和 Agentic 检索汇合。
- 预期结果：当候选存在 `rerankScore` 时，三条链路优先按 Rerank 顺序消费；没有 Rerank 分时才回退到 RRF `totalScore`，并保持去重、权限和版本过滤。
- 验证方式：Karpathy／Agentic 单测验证排序和证据包一致性。

### AC-04：引用失败时三链路使用同一受约束兜底

- 前置条件：模型输出缺少引用或引用不支撑结论。
- 操作：运行三链路回答生成。
- 预期结果：三条链路都先尝试同一批证据的受约束语义总结，再进行统一引用校验；仍不通过时返回安全降级，不把原始片段冒充答案。
- 验证方式：生成服务单测和 Chat 三模式集成测试。

### AC-05：现有调用兼容且无新增依赖

- 前置条件：已有文档上传、聊天、评测和迁移命令可用。
- 操作：运行构建、现有聊天集成测试和现有平台评测。
- 预期结果：接口字段保持兼容，不新增数据库迁移或第三方依赖，既有测试继续通过。
- 验证方式：`npm run build`、相关 Jest 测试、`npm run eval:agent-platform`。

## 边界与约束

- 黄金集使用当前仓库已有的脱敏／项目级内部样本作为可提交基线；没有主人提供的生产私有数据时，不声称“真实生产准确率”。
- 内部业务、项目和研发问题必须保持 `local_only`；黄金集不得把公网事实替代为内部证据。
- 多轮案例通过同一 `threadId` 回放；冲突案例明确客观资料、当前会话设定和历史版本的优先级。
- 不删除现有评测集，不改变数据库 schema，不修改 `.env`、密钥或 Docker 数据卷。
