# LLM 失败保护与多问题路由修复

## 背景与目标

- 背景：DeepSeek 调用失败时，Provider 将内部 Prompt 截断后作为 Mock 回答返回；一条消息包含多个独立问题时，Auto 链路可能按首题直答。
- 目标：禁止内部 Prompt 出现在用户回答中，并让多问题输入跳过单问题直答，进入深度拆解链路。
- 成功标准：失败响应不含 Prompt；多问题请求不会被首题的客观事实路由直接终止。

## 范围

- 包含：Qwen／DeepSeek Provider 的失败行为、语义路由的多问题标记、Agentic 直答门禁、相关测试与运行记录。
- 不包含：前端多轮展示重构、数据库结构、模型供应商配置或密钥修改。

## 用户与行为

### AC-01：模型失败不泄露内部 Prompt

- 前置条件：任一 Qwen／DeepSeek 调用失败。
- 操作：发起问答请求。
- 预期结果：服务记录 Provider 错误并向上抛出受控异常；回答中不出现 Mock 文本或请求 Prompt。
- 验证方式：Provider 单测模拟失败。

### AC-02：多问题输入不走单题直答

- 前置条件：语义路由标记输入含多个独立问题。
- 操作：以 Auto、Simple 或 Agentic 模式发起请求。
- 预期结果：跳过系统能力／客观事实直答和 Auto 快速直答，保留每条明确子问题并统一走 Agentic 查询规划。
- 验证方式：Agentic 服务单测断言路由与快速路径调用。

### AC-03：路由失败保守降级

- 前置条件：语义路由模型调用失败或返回非 JSON。
- 操作：发起请求。
- 预期结果：路由为 general，不依赖关键词将请求误判为可直接回答的事实。
- 验证方式：QueryIntentRouter 单测。

## 边界与约束

- 不修改 `.env`、密钥、Provider 型号或数据库。
- 保留已有 SSE `error` 事件契约。
- 当前分支为受保护 `main`，不创建或切换分支。
