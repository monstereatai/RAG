# 缺口清零实施规格

## 目标

补齐当前仓库内可独立实现的七类能力，并把无法在本地完成的线上／外部条件显式标记。

## 范围

- RAG 质量统一汇总与发布前质量门禁。
- 危险请求拦截事件持久化、查询接口与管理后台审计展示。
- 定时任务 BullMQ 调度适配、延迟／重复任务幂等与失败补偿。
- 文档索引一致性巡检与批量修复入口。
- Agent 成本、成功率、步骤准确率与恢复验证看板。
- OpenAPI 契约自动校验。
- 全量测试债务清理、并发和故障注入测试。

## 非目标与外部依赖

真实 Grafana 集群、生产告警、CI/CD 发布、备份灾备、真实低代码平台、企业 IAM／DLP／工单、生产数据库和压测资源不在本地实现范围内，需在部署清单中保持未就绪标记。

## 验收标准

- AC-01：RAG 质量接口能返回统一指标，并可作为发布前门禁退出非零。
- AC-02：高风险请求产生可查询的审计事件，管理后台可查看策略和事件。
- AC-03：定时任务在 Redis 可用时通过 BullMQ 调度，重复触发不重复执行，失败可补偿并告警／记录。
- AC-04：索引巡检返回问题分类，批量修复可重放且有结果摘要。
- AC-05：Agent 看板返回成本、成功率、步骤准确率和恢复统计。
- AC-06：OpenAPI 检查验证关键路径存在且有中文描述。
- AC-07：关键链路具备并发／故障测试，相关构建和测试命令通过；既有外部环境失败须明确记录。

## 风险

队列接入必须保持无 Redis 时的现有降级；审计事件不能记录原始敏感内容；不得新增数据库迁移。
