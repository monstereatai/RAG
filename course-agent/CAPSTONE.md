# Agent 结业验收：使用当前 RAG 项目

使用现有工具执行、审批、幂等、恢复、岗位协作和产物管理功能，不重建这些模块。结业证明的是学员个人能理解、操作、修改与排障。

## 任务

用现有岗位工作流完成一个测试业务需求，至少涉及一次受治理工具调用、一次人工审批、一次局部修订与产物验收。工具可以复用现有实现；明确哪些是真实写入、哪些是测试替身。

## 四项必过

1. 正常交付：实际产物、版本、引用与任务要求一致；工具参数、身份和审批范围可追踪。
2. 异常处理：完成 [三个工程实验](./LABS.md)，说明未知结果、重复请求、预算耗尽和服务重启分别如何处理。
3. 独立变更：现场增加一个小约束，例如特定岗位必须审批或某产物增加验收字段；自行确定改动范围并跑正常、拒绝与恢复回归。
4. 架构答辩：解释固定工作流、动态循环、单／多 Agent（智能体）的适用边界；说明并发依据、状态一致性、幂等范围与任务评测方法。

对 [实现边界](../course/IMPLEMENTATION-NOTES.md) 中已知缺口做明确说明。发现问题与修复是学习成果；未经验证的恢复能力不能通过口头宣称验收。

## 交付与判定

交付任务计划与依赖图、正常和故障执行轨迹、最终产物、任务评测报告、小变更与回归记录。任务标识连接审批、工具与业务结果。

“已完成”文本不能替代产物；测试数据指标不能替代真实运行；通过旧用例不能替代新增需求验收。关键权限、审批与重复执行断言失败时，该项标记未通过，修复并复验后完成课程。
