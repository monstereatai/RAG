# 运行治理与故障处理

长任务需同时考虑执行状态、排队、取消、外部副作用和用户可见结果。当前项目中的服务是学习入口，不预先假定其具备跨进程或跨实例的一切保证。

## 架构选择

| 问题 | 方案与代价 | 当前项目核验入口 |
| --- | --- | --- |
| 请求太长 | 请求内运行实现简单；后台任务需持久化状态、查询与重复投递处理 | productionWorkflow.startAsync／resumeAsync |
| 多个任务挤占资源 | 有界并发、队列、按用户限额；排队也计入体验耗时 | 文档队列与工作流调度，分别检查 |
| 超时后结果未知 | 超时返回不保证远端取消；查询结果、幂等与人工介入配合 | ToolExecutionService |
| 服务重启 | 状态读取、任务所有权、重入去重与恢复预算一起设计 | 生产工作流状态查询与检查点 |
| 模型或工具异常 | 分类错误、限次重试、熔断、降级；记录实际使用来源 | 模型网关与工具执行 |
| 多实例 | 进程内 Set（集合）只能去重当前进程；需核验共享协调 | 工作流 activeRuns（活动任务集） |

## 排障顺序

先找运行标识和业务终态，再看最后成功步骤、失败步骤、工具结果和依赖服务。blocked（阻断）可能是正确审批等待；failed（失败）可能是模型或依赖异常，不能仅凭状态名判定配置错或代码错。

指标用于发现异常，Trace（链路追踪）用于关联过程，业务记录用于核验副作用。调用量与费用须注明实际计量或估算，不把费用配置当作已经强制执行的预算。

## 独立演练

使用个人测试实例，选择一个任务注入工具超时或依赖不可用：记录预期、用户看到的结果、后台状态、重复执行次数与恢复步骤。再讨论同时提交十个相同业务任务时，哪些保护在进程内、哪些跨进程成立。

验收：交付一页复盘和一次小需求变更回归。已有部署可直接复用，具体部署入口见 [项目部署清单](../../docs/architecture/DEPLOYMENT_CHECKLIST.md)。
