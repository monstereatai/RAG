# Agent 任务评测：答案、行为和业务状态

答案正确不代表任务正确。例如回复“已生成交付物”，实际没有产物记录；或最终产物正确，却重复执行了写工具。

## 三类检查

| 维度 | 检查内容 | 主要判定方法 |
| --- | --- | --- |
| 答案 | 声明有证据、需求被覆盖 | 人工复核＋LLM-as-Judge（模型裁判） |
| 行为 | 工具和参数正确、权限与审批正确、依赖顺序正确 | 事件记录与确定性断言 |
| 结果 | 产物实际存在、版本正确、写入次数正确、旧结果未误覆盖 | 读取业务状态核验 |

同时记录耗时、调用数、费用估算、人工介入与重试。把预期阻断、降级完成和模型成功分开统计。工具调用次数少不天然更优，准确率提高也不意味着成本可接受。

## 固定六组任务

正常完成、错误工具参数、缺审批、重复写入请求、预算耗尽、重启后恢复。每组都预先写出预期行为与业务状态；权限被拒应计为正确阻断，不能统一算失败。

复用 [工程实验](../LABS.md) 与现有 `backend/eval/agent-task-regression.dataset.json` 的结构。开发集用来调试，保留集换任务资料与约束；核心失败可重复运行，记录成功次数／总次数，不从一次演示外推稳定性。

## 当前脚本的边界

`pnpm --dir backend run eval:agent-tasks` 和 `eval:production-workflow` 读取已有 JSON（结构化文本）中的结果字段计算指标，不会自行执行这些业务任务。先跑脚本理解指标，再将独立实际运行的状态与事件按同一格式采集；报告须带运行标识、环境和模拟标记。

`AgentEvalService` 的语义评估不能代替上述行为断言。单测验证本地分支，真实接口实验验证集成，真实业务状态验证交付，三者各自说明证据范围。

## 验收

给出一个“答案看着对但任务失败”的案例，以及一个“被阻断但安全行为正确”的案例。修复其中一个实际问题后复跑六组任务，说明改善、代价和未覆盖风险；不得只修改数据文件的 passed（通过）字段让指标变绿。
