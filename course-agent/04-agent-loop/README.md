# 受控 Agent Loop（智能体循环）：预算、状态与执行边界

源码：[AgentLoopService](../../backend/src/modules/agent-loop/agent-loop.service.ts)、[类型](../../backend/src/modules/agent-loop/agent-loop.types.ts)。策略扩展见 [规划讲义](./PLANNING.md)。

## 问题与机制

循环负责决策、动作、结果回填和再次决策。它需要明确退出条件，但单个循环函数不能独自保证完整恢复、远端动作取消或正确规划。

当前 run（执行入口）：
1. 从 initialState（初始状态）开始，工具计数清零。
2. 每轮先计算 remainingMs（剩余时间），不足则 failed（失败）。
3. 调用 decide（决策）；complete（完成）和 blocked（阻断）直接结束。
4. 工具执行前检查次数预算，经治理服务调用；模型动作使用超时包装。
5. 成功动作经 reduce（状态归约）回填后写快照。
6. 步数用尽返回 budget_exceeded（预算耗尽）。

## 源码中的取舍

- maxSteps（最大步数）最少 1、maxToolCalls（最大工具次数）最少 0。Math.max 只处理普通数值下界，不代表已校验 NaN（非法数值）、无穷大和小数。
- 工具预算在调用前拦截；blocked 和 failed 终止，避免后续建立在动作成功的假设上。
- decide 能读取预算，但当前直接 await（等待）它；需要检查其自身超时，并在决策后重新计算动作余量。当前机制不能宣称严格端到端超时。
- Promise（异步结果）超时包装限制等待，不自动取消供应商请求，远端写动作仍可能完成。
- 成功后写快照有助于观察确定状态；失败轮次的远端副作用仍要通过幂等与结果查询核对。

## 快照与故障边界

当前 run 没有自动读取快照恢复步骤和预算。重新传入旧状态执行也会重置计数，不能当作完整恢复。

snapshot.slice(0,100000) 按字符截断，可能破坏 JSON（结构化文本），并非 100KB 字节安全上限；stateHash（状态摘要）仅用于比对，不能恢复缺失数据。TTL（过期时间）默认 24 小时，不意味着过期后重复执行写动作安全。

Redis 禁用时记录跳过；启用但写入失败是另一条路径，不能笼统宣称都会吞错。事件 emit（发送）有捕获逻辑，也不能证明快照写入有同样保护。

这些是 [实现边界](../../course/IMPLEMENTATION-NOTES.md) 中的学习诊断点，不包装为已解决问题。

先完成 [三处修复实验](./lab/)：预算前置、阻断终止、成功后快照。再构造无进展决策、超慢决策、大状态和重入执行，记录已有保护与缺口。
