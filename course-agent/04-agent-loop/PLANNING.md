# 规划、状态与重新规划

## 何时需要计划

任务路径已知时，用固定工作流表达依赖；路径需要逐步探索时，用 ReAct（行动与观察交替）；需要事前审查范围时，先生成计划再执行。多 Agent（智能体）只有在角色分工、工具隔离或独立分支并行带来收益时才增加。

当前 [AgentLoopService](../../backend/src/modules/agent-loop/agent-loop.service.ts) 提供循环机制，`decide`（决策函数）来自调用方；它本身不保证模型能做出好计划。[production-workflow.plan.ts](../../backend/src/modules/workflow/production-workflow.plan.ts) 表达已知岗位依赖，不等于任意任务规划器。

## 一份可执行计划至少有什么

每步包含标识、目标、依赖、输入来源、允许工具、成功条件与失败去向。外部输入与模型文本不能自行扩大工具权限。结构校验后还要检查循环依赖、未知工具、缺失输入和预算总量。

状态区分计划版本、已确认事实、待解决问题、动作结果和剩余预算；敏感原文尽量用受权限约束的产物引用传递。仅把所有历史塞回模型，会增加成本和误用旧信息的概率。

## 重新规划的边界

工具失败可能是参数错误、暂时不可用、权限拒绝或结果未知。参数错可在预算内修正；权限拒绝不能换工具绕过；结果未知先查远端，不能自动重复写入。新证据推翻旧假设时，失效相关步骤与下游产物，保留无关结果。

定义无进展检测：相同工具与参数重复且没有新证据时，收尾、澄清或转人工；不能只依赖模型主动说完成。重新规划不刷新总预算，审批后计划变更应重新检查授权范围。

## 工程实验

在已有循环代码实验中设计两个策略：固定三步执行、根据观察选择下一工具。输入同一任务，再分别注入工具拒绝、空证据、重复观察与预算耗尽。

验收：提交计划与状态变化表，解释每次重新规划依据；写操作次数符合预期，循环最终有明确终态。独立任务：业务要求某一步增加人工确认，自行确定状态字段和恢复范围，不直接复制参考循环。
