# 高级 Agent 开发：受控执行、协作与工程验收

目标：独立设计、修改、运行和排障一个具有工具执行、审批、恢复与评测能力的 Agent（智能体）。沿用当前 RAG 项目与已有专题目录，不限制学习天数。

入口：[共同指南](../course/GUIDE.md) · [实现边界](../course/IMPLEMENTATION-NOTES.md) · [工程实验](./LABS.md) · [结业验收](./CAPSTONE.md)。

AI 应用课的模型调用、检索问答和权限是前置。代码专题保留原编号，以下模块给出完整学习顺序。

## 模块 1：任务建模与架构选择

阅读：[架构专题](./01-architecture/README.md)、[自测](./01-architecture/quiz.md)、[工作流优先决策](../docs/architecture-decisions/ADR-001-workflow-first.md)。

比较：普通函数适合确定性逻辑；工作流适合已知依赖；单 Agent 适合需要动态选工具的任务；多 Agent 需要岗位责任或并行收益支撑。复杂不是使用多 Agent 的充分理由。

实验：对同一业务目标分别画固定工作流与动态规划方案，标注状态、工具、副作用、验收条件和退出条件。

验收：说清为什么当前六岗位系统采用依赖编排，何时应简化成普通服务。

## 模块 2：工具设计与外部能力接入

阅读：[工具注册与策略](./02-tool-registry/README.md)、[自测](./02-tool-registry/quiz.md)、[MCP（模型上下文协议）工具接入](./07-routing-ecosystem/README.md)、[自测](./07-routing-ecosystem/quiz.md)。

设计要求：工具名称表达业务动作；参数有类型、必填项、业务范围和校验；返回业务结果与可分类错误。身份和审批凭据来自可信请求上下文，不能由模型填写后直接相信。

比较：本地工具与外部协议工具；粗粒度业务工具与底层通用工具；只读与写入工具。工具加载成功、模型选择成功、受治理执行成功是三层不同验收。

实验：复用现有工具，用正常、缺参、非法范围、无权限和未审批输入验证；外部工具增加服务不可用用例。

验收：为一个工具写完整契约，并验证没有绕开 Tool Registry（工具注册表）与执行策略。

## 模块 3：幂等、结果未知与副作用治理

阅读：[幂等与审计](./03-idempotency/README.md)、[自测](./03-idempotency/quiz.md)、[工具工程实验](./LABS.md)。

比较：请求超时不代表远端未执行；重试、结果查询与补偿各有前提。幂等键绑定业务操作身份，不应只靠参数相同或 TTL（过期时间）判断是否是新意图。

实验：串行重复、并发重复、执行后响应丢失、缓存结果重放、幂等记录过期；检查实际业务写入次数。

验收：区分 success（成功）、recovered（复用成功结果）、blocked（阻断）、failed（失败）与存储里的 unknown（结果未知）。明确本地锁不能代替远端业务幂等。

## 模块 4：受控循环与规划执行

阅读：[循环内核](./04-agent-loop/README.md)、[自测](./04-agent-loop/quiz.md)、[代码实验](./04-agent-loop/lab/)、[规划与状态讲义](./04-agent-loop/PLANNING.md)。

比较：ReAct（行动与观察交替）适合逐步探索；计划后执行适合需要提前审查的任务；固定 DAG（有向无环依赖图）适合已知岗位依赖。规划生成不等于计划可以安全执行。

实验：完成代码修复实验；分别构造正确完成、工具阻断、无进展循环和预算耗尽；更换决策策略对比行为。

验收：每个计划步骤有输入、依赖、成功条件和失败去向；预算限制要覆盖决策、动作与重新规划。

## 模块 5：审批、持久化与恢复

阅读：[审批与恢复](./05-human-approval/README.md)、[自测](./05-human-approval/quiz.md)、[审批工程实验](./LABS.md)。

比较：事件通知／持久化状态／调度恢复是不同层次；快照记录不等于可恢复执行；审批应绑定具体动作、参数和版本。

当前课程将 Chat（问答）审批、Agent Loop 快照和生产工作流分别说明，不能互相替代能力证明。

验收：待审批时后续动作没有执行；批准后才继续；驳回和修订路径明确；测试实例重启后验证恢复且已完成写操作不重复。发现实现缺口须记录并回归验证。

## 模块 6：岗位协作与产物依赖

阅读：[SOP（标准作业流程）协作](./06-sop-workflow/README.md)、[自测](./06-sop-workflow/quiz.md)、[生产工作流操作](../docs/PRODUCTION_WORKFLOW_USAGE.md)。

比较：顺序执行／独立分支并发；整任务重跑／局部重跑；模型自由协作／明确岗位契约。并发依据真实数据依赖，不能仅看节点画在同一行。

实验：使用现有岗位组合；驳回一个中间岗位，检查无关分支保留、受影响下游过期和修订后重跑范围。

验收：检查 Artifact（结构化产物）的字段、版本、来源、依赖及人工验收；不把“有一段文本”当作交付完成。

## 模块 7：任务评测与执行轨迹

阅读：[评测与运营](./08-eval-ops/README.md)、[自测](./08-eval-ops/quiz.md)、[任务级评测补充](./08-eval-ops/TASK-EVALUATION.md)。

评测分三类：答案语义、执行行为、最终业务状态。LLM-as-Judge（模型裁判）辅助语义判断；权限、工具参数、调用次数与最终写入状态用确定性断言。

实验：同一任务评估正常、错误参数、缺审批、重复执行、预算耗尽和恢复六种轨迹，修复一项后跑回归。

验收：报告既有任务结果，也有代价与失败原因；固定数据文件上的指标计算不冒充真实 Agent 执行评测。

## 模块 8：运行治理与综合交付

阅读：[运行治理](./08-eval-ops/OPERATIONS.md)、[结业验收](./CAPSTONE.md)。复用 AI 应用课的部署、权限、追踪和数据治理。

比较：请求内执行／后台任务；单实例内存状态／持久化协调；串行／有界并发；自动恢复／人工接管。Skills（技能）与领域路由用于按需选择任务知识和管线，不应额外制造无收益的层级。

验收：在当前项目完成一个真实约束下的小变更，定位一次失败并给出运行证据。已有高级能力以个人独立操作和修改证明，不要求另建项目。浏览器控制、自由群体协作可作为后续方向，不作为这两门课的毕业前置。
