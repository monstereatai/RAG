# 课程使用指南

两门课以独立负责高级 AI 应用与 Agent（智能体）项目为目标，按能力验收，不规定学习天数。当前 RAG（检索增强生成）项目就是贯穿案例与结业项目。

当前实验通过项、既有失败与真实服务未验证项见 [验证记录](./VERIFICATION.md)。

## 学习结构

- [AI 应用课程](./README.md)：业务与模型 → 数据与检索 → 问答与治理 → 评测与交付。
- [Agent 课程](../course-agent/README.md)：任务与工具 → 循环与恢复 → 协作 → 评测与运行治理。
- 先完成 AI 应用课的问答链路，再进入 Agent 的循环与规划。两门课共用业务数据、运行记录与架构说明。

目录沿用现有名称，避免旧链接失效。大纲中的“模块”是新的学习顺序；原编号目录是源码专题材料，不要求按目录编号阅读。新增文件使用英文名：专题讲义放所属目录，工程实验集中在各课 `LABS.md`，结业验收在各课 `CAPSTONE.md`，共同校正记录在 [实现边界](./IMPLEMENTATION-NOTES.md)。

## 每章怎么学

1. 明确业务问题、输入输出和成功标准。
2. 比较两种以上方案，说明当前项目选择的理由与代价。
3. 读核心函数、状态流转与异常分支；行号只是导航，以函数名和当前源码为准。
4. 做基础练习、工程实验，再做只给需求与验收标准的独立任务。
5. 自测后讲清取舍，并保留一次正常和一次异常运行证据。

有后端经验可先做自测和实验，已掌握的部分跳读；薄弱部分回看。个人七天冲刺安排只用于选择复习重点，不能替代全课验收，也不限制课程深度。

## 运行实验

实验分三层：
- 基础层：切片、BM25（关键词相关性算法）、Agent Loop（智能体循环）的填空或修复练习。
- 工程层：混合检索对比、工具幂等、审批恢复和任务评测，入口见各课 `LABS.md`。
- 独立层：在当前 RAG 项目完成小需求变更、回归与故障定位。

Node.js、pnpm 使用项目声明版本。基础代码实验不依赖外部模型和数据库；真实联调需要已有服务与测试账号。故障演练使用个人测试实例，部署使用现有部署说明与目标环境的发布流程。

三个基础代码实验原地运行，命令在仓库根目录执行：

```bash
pnpm --dir backend exec jest --config ../course/02-chunking/lab/jest.inplace.config.json chunking.student --runInBand
pnpm --dir backend exec jest --config ../course/04-bm25/lab/jest.inplace.config.json bm25.student --runInBand
pnpm --dir backend exec jest --config ../course-agent/04-agent-loop/lab/jest.inplace.config.json agent-loop.student --runInBand
```

实验配置沿用仓库现有 Jest（测试框架）环境。依赖版本变化时，先确认配置内的环境路径，不把框架启动失败当作学员实现错误。填空版对应缺失功能的断言应失败；已有正确行为的测试可以通过。完成后对应测试全部通过，并解释测试覆盖不到的边界。

## 通过标准

基础自测沿用各专题 12 分制，达到 10 分；新专题采用文内验收。自测通过只证明基础理解。工程实验还须提供：

- 运行环境、输入、预期、实际、关联运行 ID（标识）。
- 正常与异常路径，修改前后结果和影响范围。
- 一段不看代码的解释：为什么选这个方案、另一个方案何时更合适。

测试发现现有实现不符合预期时，记录为未通过，定位问题并提出修复与回归方案；不能为了结业修改期望值。课程本身不把“发现缺陷”当作学员失败，但涉及该能力的工程验收须修复后重新验证。

结业使用 [AI 应用验收](./CAPSTONE.md) 与 [Agent 验收](../course-agent/CAPSTONE.md)。高级能力以独立修改、排障和解释取舍来证明，既有项目功能和历史测试报告是素材，不能代替个人完成验收。

## 材料维护

每个模块必须具备：问题、方案比较、源码入口、实现边界、实验、验收。优先复用现有测试和数据，避免重复建设。

讲义标明“已由代码确认”“教学简化”“待运行验证”；不得把计划、注释或接口名当作实现证明。纠正知识点时同步检查自测答案、口播稿和实验。新增链接须能解析，实验命令须实际验证或注明未运行的条件。同步更新项目 ROADMAP（进度记录）。
