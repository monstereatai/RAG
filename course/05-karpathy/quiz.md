## 四、代码审查题（2 分）

9. 同学实现的回答链路：

```ts
async answer(query: string) {
  const chunks = await this.hybridRetrieve(query, 5);
  if (chunks.length > 0) {
    return this.llm.invoke(`根据以下资料回答：\n${chunks.map(c => c.content).join('\n')}\n问题：${query}`);
  }
  return '抱歉，我没有找到相关资料。';
}
```

对照本节 answer() 主线，指出至少 3 处缺失的能力（不算 Prompt 细节）。

## 参考答案（先做完再看）

1. **对**。直答只查 PG 精确问题，零向量计算成本（§3.1）。
2. **错**。各路自带 catch 降级（Obsidian 显式 catch；检索层内部有降级结构），单路失败链路继续（§3.2，与第 8 课"sum 变 max 的前提"呼应）。
3. **错**。安全降级：confidence=0 + 补充信息指引，绝不硬答（§3.4）。
4. **B**。正式检索充分时它优先；不足时已审核的人工证据顶到前面（§3.3）。
5. **B**。检索快照跨阶段复用（§3.2）。
6. **B**。循环必须有计数器（坑点 2）。
7. 证据顺序即信任排序：正式检索充分说明语料覆盖良好，按检索相关度主导；正式不足时，已审核（人工背书）的 Base Case 证据更可信，让它主导上下文、占据注意力最强的首尾位置——排序不是实现细节，是对"谁更可信"的表达。
8. 知识库场景：错误答案误导决策/合规风险 >> 空答案的体验损失，且"拒答+指引"可引导用户补充信息后二次提问，损失可回收。闲聊/创意场景不成立：拒绝回答一个虚构性问题没有价值，模型基于参数知识自由发挥反而是预期行为——**降级策略是场景的函数**。
9. ① 无意图分档与 profile（所有 query 一套 topK/预算）；② 无门禁：`chunks.length > 0` ≠ 充分，弱相关照样放行生成；③ 无联网补证：不足直接拒答，丢掉了"再救一次"的机会；④ 无安全降级的结构化表达（confidence/reason 溯源，前端无法区分"确认不足"与"系统故障"）；⑤ 无直答/纠错短路（每个问题都付全量检索成本）；⑥ 三路并发缺失（若扩展多源，延迟累加）。
