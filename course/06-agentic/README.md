## 问题与方案比较

事实查询通常不需要多步规划。多文档比较可能需要子问题和反复取证；既可用固定工作流，也可由模型在预算内动态选择。选择依据是需求复杂度、证据充分性和成本要求，不仅是问题长度。

## 当前真实入口

追踪 run（执行入口）的模式分支和 assessFastPath（快速检索评估），再看 initGraph（图初始化）。routeNode（路由函数）单独存在，不代表它是当前编译图的入口；必须检查 START（开始）连接到哪里。

当前图主线：
```text
queryAugment（查询扩展）→ retrieval（检索）→ sufficiency（充分性）
  不足且允许补证 → webSearchFallback（联网补证）→ sufficiency
  可生成 → rerank（重排）→ generate（生成）
  → humanApprovalNode（审批节点）→ reflection（反思）或结束
  反思可在预算内回到检索
```

审批节点当前对 pending（待审批）仍进入反思，不是可靠暂停点，详见 [实现边界](../IMPLEMENTATION-NOTES.md)。检查点是否存在和恢复后是否重复执行是两个问题。

## 子问题、证据与预算

短实体或原子事实问题保留原题；复杂任务的子问题要明确依赖、证据和成功条件，不能平白增加必须完成的要求。已审核 Base Case（纠错知识）、正式检索和外部补证应按实际实现记录来源与权限。

预算覆盖扩展数量、检索次数、候选量、重排数量、模型动作与总耗时。读取字段后还要找到消耗和退出分支，不能仅凭配置名判断已限制。

## 流式事件怎么验收

SSE（服务端事件流）用于传递文本、执行进度和结果。事件是应用公开的执行轨迹，不是模型内部完整思考。区分“已输出部分文本”和“任务完成”。

检查控制器在成功、异常和断开场景的终态。resume（审批继续）事件不自动提供网络断线重连和事件去重；这些需要独立的客户端与服务端协议。

## 排障与实验

用精确事实、多文档比较、库外公开问题各跑三模式，记录来源、路由、补证次数、总耗时和最终结果。使用当前接口定义观察事件，不增加不存在的请求参数。

坏输入重复取证时，查预算、证据变化与退出条件；事件不结束时，查控制器异常收尾和连接关闭。模式路由实验应改变证据充分性或任务复杂度，并验证短问题也可能复杂、长问题也可能直接回答。
