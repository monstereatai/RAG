# 高级 AI 应用开发：基于当前 RAG 项目的原理与工程实战

目标：独立完成业务建模、模型调用、知识入库、检索问答、评测调优与部署排障，并解释架构取舍。以能力验收，不限定天数。

入口：[使用指南](./GUIDE.md) · [实现边界与校正](./IMPLEMENTATION-NOTES.md) · [工程实验](./LABS.md) · [结业验收](./CAPSTONE.md) · [全局流程图](./diagrams.md)。

保留原专题目录与代码实验；以下八个模块是学习顺序。已有项目直接作为实战系统，不要求重建。

## 模块 1：业务需求与应用架构

问题：先确定用户要完成什么、证据来自哪里、错误成本和响应要求是什么，再决定是否需要 RAG。

方案比较：直接模型问答适合无需私有证据的内容生成；数据库查询适合精确结构化事实；RAG 适合引用资料作答；工作流适合步骤明确的任务。不要把所有需求都塞进检索或 Agent。

阅读：[Provider（服务适配层）](./01-providers/README.md)、[自测](./01-providers/quiz.md)、[项目背景](../docs/PROJECT_BACKGROUND.md)。源码：`backend/src/providers/llm/llm-provider.interface.ts`、`backend/src/app.module.ts`。

实验：画出一个现有业务请求经过的服务、数据源与权限边界；用本地假实现验证上层依赖接口。新增服务实现仍需要依赖注入注册，环境变量不能凭空加载未注册实现。

验收：用一页设计说明业务目标、候选方案、选择理由与至少一个不适用场景。

## 模块 2：模型调用、结构化输出与流式交互

问题：模型输出可能格式错误、超时或中途断流，业务接口仍要有明确结果。

阅读：[模型应用讲义与实操](./01-providers/MODEL-APPLICATION.md)。源码：`backend/src/providers/llm/llm-gateway.policy.ts`、`backend/src/providers/llm/qwen-llm.provider.ts`、`backend/src/modules/document/document-metadata.extractor.ts`。

方案比较：普通文本、结构化输出、工具调用分别适用于展示、机器消费和执行动作；流式输出提升可感知响应速度，但不代表任务已完成。

验收：处理一次格式错误、一次服务超时和一次流式中断；区分实际模型、降级来源、解析成功与业务正确。

## 模块 3：数据入库与索引一致性

问题：原件、切片、版本和多个索引如何保持可追溯，索引失败时什么内容可以被检索？

阅读：[解析与切片](./02-chunking/README.md)、[自测](./02-chunking/quiz.md)、[代码实验](./02-chunking/lab/)、[向量工程](./03-embedding/README.md)、[自测](./03-embedding/quiz.md)。

源码：`document.service.ts`、`document-queue.service.ts`、`chunking.util.ts` 位于 `backend/src/modules/document/`；向量存储位于 `backend/src/providers/vector-store/`。

方案比较：固定长度／结构切片／父子切片；同步入库／异步队列；同库事务／跨索引状态与补偿。固定长度不是一概错误，需看文档结构与实测结果。

实验：同一组含表格、版本冲突的文档做切片对比；检查 draft（草稿）、effective（生效）、deprecated（废弃）与权限过滤；在测试实例制造一路索引失败并检查查询可见性。

验收：能从答案引用定位回原件和版本，并解释重试如何避免重复数据。没有观测证据的跨库原子性不得宣称已保证。

## 模块 4：检索、融合与重排

阅读：[向量工程](./03-embedding/README.md)、[BM25（关键词相关性算法）](./04-bm25/README.md)、[自测](./04-bm25/quiz.md)、[代码实验](./04-bm25/lab/)。

方案比较：关键词适合精确术语，向量适合语义匹配；RRF（倒数排名融合）减少分数量纲差异，重排则增加模型调用成本。图谱适合明确关系查询，需验证其相对普通检索的增益。

实验：[混合检索四组对照](./LABS.md)。图谱扩展阅读：`backend/src/providers/neo4j/`（以实际目录为准，可通过文件检索定位图谱提供方）。

验收：手算一例打分，解释项目去重词项的简化；用同一数据集比较向量、关键词、混合、混合加重排，说明改善与代价。

## 模块 5：证据驱动的问答与三模式

阅读：[证据门禁](./05-karpathy/README.md)、[自测](./05-karpathy/quiz.md)、[Agentic（智能体式）检索编排](./06-agentic/README.md)、[自测](./06-agentic/quiz.md)。

方案比较：固定检索链路控制成本；Auto（自动模式）按复杂度和证据选择路径；Agentic 以预算约束多步取证。问题长度只是一项信号，不能单独作为升级标准。

实验：覆盖精确已审核问答、一般事实、多文档对比、库外公开问题和无法确定的问题；记录最终路由、召回来源、补证次数和引用。

验收：区分 Base Case（已审核纠错知识）、正式知识与外部证据；查不到时能明确缺失信息；前端展示执行事件，不声称展示模型内部思考。

## 模块 6：多租户、记忆、缓存与安全

阅读：[隔离与记忆](./07-multitenant/README.md)、[自测](./07-multitenant/quiz.md)。源码：`backend/src/modules/memory/`、`backend/src/common/`。

方案比较：完整历史／摘要／按需历史检索；请求缓存／检索缓存；角色权限／文档级 ACL（访问控制）。缓存键必须体现身份、范围和知识版本，不能让缓存绕过权限或失效知识过滤。

实验：用户 A 的私有资料不可被 B 经检索、缓存、历史或图谱获取；验证长期记忆新增、纠正与删除；将提示注入内容当待检索数据，不当执行指令。

验收：写出数据流与隔离检查表，解释哪类信息应进入长期记忆以及错误记忆如何处理。

## 模块 7：评测驱动的质量、成本与性能优化

阅读：[调优专题](./08-tuning/README.md)、[自测](./08-tuning/quiz.md)、[评测讲义](./08-tuning/EVALUATION.md)。

方案比较：词命中只能辅助诊断，相关性与引用需单独判断；模型裁判适合语义辅助，确定性规则适合权限、版本和格式。一次只改变一个主要变量。

实验：复用模块 4 数据，选择一个失败案例进行归因与修复，保留开发集和未参与调参的保留集。记录模型调用数、总耗时、首段响应、降级次数和成本估算口径。

验收：提交优化前后对比；10 题小样本能支持案例分析，不能代表整体业务准确率，少量请求不能支撑稳定的 p99（第 99 百分位延迟）结论。

## 模块 8：部署、运行排障与结业

阅读：[部署清单](../docs/architecture/DEPLOYMENT_CHECKLIST.md)、[部署说明](../docs/architecture/DEPLOYMENT.md)、[工程实验](./LABS.md)、[结业验收](./CAPSTONE.md)。

方案比较：单实例与多实例的状态存储、后台任务、限流与缓存一致性；日志、指标与 Trace（链路追踪）的不同用途。

验收：操作当前项目，在测试环境完成依赖故障与恢复验证，并独立完成一个小需求变更。已有部署可直接使用；重新部署是环境练习，不是重复开发项目。
