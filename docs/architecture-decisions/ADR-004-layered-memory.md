# ADR-004：分层记忆并区分记忆与知识

- 状态：accepted
- 日期：2026-08-03
- 影响范围：跨会话连续性、Token 成本、LangGraph 恢复

## 背景

把全部历史对话塞进 Prompt 会持续增加 Token、延迟和噪声；把用户说过的话直接当企业事实，又会污染知识库。执行状态、用户偏好和已审核业务知识的生命周期不同。

## 备选方案

1. 全量上下文：信息完整，但成本不可控且容易超窗。
2. 单段摘要：成本低，但数字、版本和开放问题容易丢失。
3. 分层记忆：全量历史、短期窗口、结构化摘要、长期偏好、治理知识分别存储。

## 决策

全量消息落库用于追溯；Redis 保存最近会话与短期窗口；超窗内容压缩为 facts、decisions、openIssues 和 sourceDigest，并保留最近原文；用户偏好进入长期记忆；稳定业务事实进入 RAG／Obsidian；LangGraph Checkpointer 独立保存执行状态。

## 代价

多套存储会带来一致性、过期和删除治理成本；摘要仍可能损失信息，因此不能把摘要当唯一事实源。

## 验证指标

跨会话事实命中率、摘要事实保留率、Token 节省率、上下文构建 P95、错误记忆率、Checkpointer 重启恢复率。

## 回滚条件

某类长期记忆错误率不可接受时，停止自动写入，改为候选记忆＋用户确认；摘要失真时扩大原文窗口并回到来源消息。
