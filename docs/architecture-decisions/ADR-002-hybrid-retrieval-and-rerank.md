# ADR-002：多路召回、RRF 融合与条件式 Rerank

- 状态：accepted
- 日期：2026-08-03
- 影响范围：中文业务知识检索、版本号／活动名／接口字段召回

## 背景

游戏官网和活动产研资料同时包含自然语言、专有名词、版本号、数值、接口字段和表格。单独向量检索容易漏精确词，单独 BM25／ES 又不理解同义表达。

## 备选方案

1. 只用向量检索：语义泛化好，精确字段和罕见词不稳定。
2. 只用 BM25／ES：精确词强，同义改写和自然语言弱。
3. 多路召回＋RRF＋Rerank：召回和精排分层，但增加延迟与外部依赖。

## 决策

向量、BM25、Elasticsearch 和可选 GraphRAG 并行召回，用 RRF 做跨评分域融合；候选较多或查询复杂时调用 DashScope Rerank，失败时保留融合排序；最终做相邻块扩展、去重、来源多样性和上下文预算控制。

## 代价

链路更长，索引一致性、延迟和降级行为更难治理。Rerank 不是为了“显得高级”，只有 nDCG／MRR 的真实收益能覆盖耗时和成本时才保留。

## 验证指标

Recall@K、MRR、nDCG、TopK 来源多样性、同义改写排序稳定性、过滤正确率、Rerank 增益、P50／P95、降级前后质量差。

## 回滚条件

若真实业务集上的 Rerank 增益低于约定阈值或 P95 超过 SLA，则按查询类型条件启用；若某一路长期无增益，则停止该路召回并保留离线复验入口。
