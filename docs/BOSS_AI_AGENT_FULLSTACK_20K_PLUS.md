## 二、岗位要求归纳

### 1．这是「产品工程＋Agent 工程」岗位，不是只会调模型

高薪样本都要求端到端交付：需求澄清、架构设计、前端交互、后端 API、数据链路、模型集成、部署与迭代。企业平台型岗位还要求能把 Agent 做成可运营的能力，而不是做一次性聊天 Demo。

| 能力层 | 高频要求 | 对应可证明产物 |
| --- | --- | --- |
| 前端与交互 | React／Next.js／TypeScript 为主；部分岗位要求流式输出、动态 UI、多端体验 | Chat／工作流 UI、SSE 消费、可恢复任务视图、后台治理页面 |
| 后端与服务 | Node.js、Python、Go、Java 至少有一条主栈；API、微服务、网关、鉴权、并发与稳定性 | NestJS／FastAPI 服务、JWT／RBAC、多租户、限流／超时／重试、Docker 部署 |
| LLM 应用 | Prompt、Function Calling／Tool Calling、上下文管理、模型接入与降级 | Provider 抽象、多模型切换、工具 Schema、预算控制、流式链路 |
| RAG 与知识 | 向量库、检索、知识库、引用；部分 JD 直接点名 RAG | 文档解析、混合检索、Rerank、权限／版本过滤、引用与拒答、评测集 |
| Agent 工程 | 编排、调度、事件、任务分解、工具集成、模型集成、评测 | LangGraph／状态机、Checkpoint、人工审批、工具白名单、运行追踪与 Bad Case 回归 |
| 平台化与交付 | 平台架构、网关、开放集成、客户交付、上线后迭代 | MCP／API、可导出交接包、审计、可观测、运行指标、灰度与回滚方案 |

### 2．20K 以上的经验门槛

- 主流门槛是 **3–5 年＋本科**；腾讯智能体、360 Agent 平台等更偏平台／架构的岗位上升到 **5–10 年**。
- 20–30K 的创业公司也会给 1–3 年或学历不限的入口，但通常要求一个人能完成需求到上线，并能快速使用 AI 编程工具，不是初级切图／接口拼装岗位。
- 薪资达到 30K＋后，JD 的关键词从「开发功能」明显转向「架构」「编排／网关」「高可用」「工程化」「交付」「平台能力」。

### 3．招聘方最看重的三类证据

1. **能跑的 AI 产品**：前端、服务端、模型调用、数据与部署一起跑通；只展示 Notebook、Prompt 或静态页面说服力很弱。
2. **Agent 可控性**：工具调用 Schema、权限、超时／重试、预算、人工审批、任务状态恢复、运行追踪和评测闭环。
3. **业务闭环**：不是泛泛的「接入大模型」，而是说明在客服、知识管理、流程自动化、创作、电商／营销、企业 IT 等具体场景中，Agent 如何接收输入、取证、执行、交付与复盘。

## 三、对「AI Agent 全栈」与「AI Agent 应用全栈」的区分

| 维度 | AI Agent 全栈开发 | AI Agent 应用全栈开发 |
| --- | --- | --- |
| 重心 | Agent 平台／编排引擎／网关／任务运行时 | 具体业务产品与交付，如电商、企业服务、创作、知识助手 |
| 常见关键词 | orchestration、scheduler、event、gateway、evaluation、platform | RAG、对话体验、业务流程、API 契约、SaaS、交付、迭代 |
| 更高薪资的分水岭 | 能设计多 Agent、工具治理、状态恢复与运营平台 | 能把 AI 能力变成稳定可用、可衡量、可持续迭代的业务功能 |
| 作品集重点 | 运行时架构图、状态机、任务／工具审计、评测数据 | 真实用户路径、端到端 Demo、业务指标／验收、上线质量 |

## 四、投递与面试使用建议

- 投递标题可覆盖：`AI Agent 全栈开发工程师`、`智能体全栈开发工程师`、`AI Agent 应用全栈研发工程师`、`AI 应用研发工程师（全栈）`、`AI Native 全栈工程师`。
- 简历首屏优先写「端到端 AI 产品交付」和可量化的工程能力；把 RAG、Agent、MCP、评测、治理拆成可验证模块，而不是堆技术名词。
- 面试准备应优先覆盖：SSE 流式与中断恢复、RAG 可信引用与权限过滤、Agent 工具调用治理、任务审批／重试／Checkpoint、多模型 Provider、指标与 Bad Case 回归。
- 需要谨慎：`15–30K`、`18–30K` 等岗位未被纳入本表，因为其薪资下限不足 20K；不能只看上限判断岗位定位。
