# DeepSeek · 高级 AI 应用 / Agent 开发岗 — 10 小时面试冲刺指南

> **用途**：面试前 10 小时倒排冲刺；面试后持续迭代，每次面试完回来更新第 8 节。
> **原则**：只背能脱稿讲的，只记能扛追问的，边界数字不吹。本指南是「执行清单」，不是知识手册——知识细节去引用里的原文档查。
> **依据**：项目 `docs/interview/` 既有体系 + `ROADMAP.md` 真实进度。面试时一切数字以 ROADMAP 实际评测输出为准。
> **目标岗位主线**：RAG 质量 → Agentic Workflow → 引用拒答 → 评测 → 稳定性 → 成本与业务结果。
> 更新时间：2026-08-08

## 0. 两分钟使用说明

- **三档出口**：每个难点都按「30 秒结论 → 2 分钟展开 → 追问深挖」三层准备。面试先给 30 秒结论，被追问再展开。
- **打勾制**：每完成一项把 `[ ]` 改成 `[x]`，进度一目了然。
- **时间不够怎么办**：只保第 1、4、5、6 节，其余跳过。
- **面试后**：把现场新题、卡壳点、追问记进第 8 节，再回填第 6 节。

## 1. 项目一句话定位（必背，开场 30 秒）

> **一句话**：企业级 Agentic RAG 知识治理与问答平台——文档结构化入库、混合检索、Agentic 编排、引用校验、评测闭环，落地在游戏官网/活动营销场景。

**2 分钟展开（STAR 结构）**：
- **背景**：游戏活动/官网资料分散在 PRD、设计稿、接口文档、埋点规范、复盘里，运营和产研查询靠人肉翻文档，效率低、口径不一。
- **动作**：从 0 到 1 搭建 RAG + Agent 工作台。文档解析→结构化切片→Embedding→Milvus+BM25/ES 混合检索→Rerank→生成→引用校验；simple/auto/agentic 三档路由；多 Agent 管线；记忆分层；评测闭环。
- **结果**：本地工程成熟度 93/100，项目级评测 28/28（本地模拟集），后端 40 Suites/177 Tests 全绿。
- **边界（必须主动说）**：28/28 是本地模拟数据，真实毒题集和真实业务数据仍在补数，生产未落地。

## 3. 六条主线 30 秒背诵卡

### 3.1 检索质量（怎么查得准）

- **30 秒**：三层保召回——Milvus 向量检索 + 本地 BM25 + Elasticsearch IK 中文分词，结果用 RRF 分数融合，再 Rerank 提精度；切片用结构化切分（章节路径 + 表头保留 + 代码块原子），避免信息割裂。
- **追问点**：为什么不用单一检索？中文分词谁负责？RRF 比加权好在哪？切片 500/50 参数怎么来的？权限怎么在检索层过滤（userId 物理隔离）？

### 3.2 Agentic 编排（为什么这样编）

- **30 秒**：simple 走 Karpathy 快路径；auto 先快路径再用 sufficiency gate 判断是否升级；agentic 走完整 research 链：routing → query augment → retrieval → sufficiency → web search → rerank → generate → citation → reflection。用 LangGraph 状态机，最大步骤防死循环。
- **追问点**：sufficiency 怎么量化？什么时候触发 web search？query augment 扩什么？reflection 后悔改什么？

### 3.3 引用与拒答（怎么撑住）

- **30 秒**：答案里的每个论断要能回指证据片段，检索不足或低相关时直接拒答，不硬答；Bad Case 飞轮把已审核负反馈写进独立 Milvus collection，生成前召回相似纠错样本，防止同样的错反复犯。
- **追问点**：引用校验失败的兜底策略？拒答阈值谁定？Bad Case 会不会覆盖正常知识？

### 3.4 评测（怎么证明）

- **30 秒**：本地建了两套集子——193 条泛企业 + 96 条游戏营销专项，覆盖 7 类场景；用 LLM-as-Judge 7 个维度打标，项目级评测 28/28。全部是本地模拟数据，真实毒题集在补。
- **追问点**：Judge 用什么模型？7 个维度是什么？数据怎么去污染？28/28 是过拟合吗？

### 3.5 稳定性与降级（怎么保证）

- **30 秒**：Qwen Provider 默认超时从 20s 提到 60s、预算 75s、maxTokens 4096、重试退避；检索链路 Milvus 超时快速失败→短期熔断→BM25 降级；Redis 未配置自动降级同步处理；完整 DAG 连续 3 次回放 18/18 模型调用成功、0 降级。
- **追问点**：降级策略有哪些层？熔断参数？30 次长期复验为什么还没做？

### 3.6 成本与业务结果（怎么算账）

- **30 秒**：本地有 LLM 调用计数、token 估算、p50/p95 性能指标；产物和 QA 用独立 BullMQ 队列控制并发。真实业务结果（召回率、采纳率、工时节省）还在补数，不冒充。
- **追问点**：token 怎么省（缓存/记忆/query 扩展）？成本报表口径？延迟 SLA 现状？

## 6. 高频问题 30 秒 / 2 分钟框架（本岗）

> 每个问题：先一句结论，被追问再展开 2 分钟，最后落到数字和边界。

1. **项目解决什么业务问题？** → 见第 1 节 STAR。
2. **RAG 主链路讲一遍？** → 入库→切片→Embedding→混合检索→Rerank→生成→引用校验；三档路由入口 `rag/agentic/agentic-rag.service.ts`。
3. **为什么混合检索 + RRF？** → 向量管语义、BM25 管精确词/中文词、ES 管分词检索；RRF 无需调权稳定融合，保留分数做质量闸门。
4. **切片策略怎么设计？** → 结构化切分：叶子 chunk 重复章节路径、代码块原子、表格整行+表头保留、接口/测试/版本规则加内容类型标识。
5. **Agentic 为什么这样编排？** → 快路径优先省成本，sufficiency 不足才升级；完整链 8 步，LangGraph 状态机 + 最大步骤防死循环。
6. **怎么防幻觉？** → 三层：引用校验（论断回指片段）+ 低相关拒答 + Bad Case 飞轮（相似纠错召回）。
7. **多租户隔离怎么做？** → userId 贯穿 DB、Redis 缓存、Milvus 向量、内存 BM25 四层物理/逻辑隔离，检索层按权限过滤。
8. **评测怎么做？** → LLM-as-Judge 7 维 + 两套本地集（193+96）；指标含召回/排序/忠实度/引用/拒答；28/28 是本地口径。
9. **记忆系统怎么分层？** → 短期 Redis 滑动窗口 30 轮 + LLM 摘要压缩；长期 Mem0（cloud/local 双模式）按 user/session 分层。
10. **稳定性怎么保证？** → Provider 超时/预算/重试参数修正 + 检索熔断降级 + 完整 DAG 3 次 18/18 回放证据。
11. **多 Agent 怎么编排？为什么？** → Supervisor 管线 researcher/analyst/writer/critic/editor，职责单一、可观测、可评测；业务场景也可走 6 岗位 DAG。
12. **Tool / MCP / Skill 什么关系？** → Tool 是函数执行单元，MCP 是工具标准化传输协议，Skill 是带流程的知识包；项目暴露 11 个 MCP 工具给 AI 编程工具取上下文。
13. **GraphRAG 做了什么？** → Neo4j 存实体关系，实体抽取、schema/entities/relationships 运营接口，业务图谱种子已导入。
14. **成本和延迟怎么优化？** → 快路径优先、query 扩展限量、记忆/缓存减少重复调用；本地有 token 估算和 p50/p95 指标；严格延迟 SLA 仍未达标。
15. **生产边界在哪？** → 真实毒题集、真实组织主数据、30 次复验、生产部署四项未完成，其余本地工程全闭环。

## 9. 维护与迭代说明

1. **每次面试后**：先填第 8 节，再回填第 6 节，最后更新第 4 节数字表（以 `ROADMAP.md` 和实际评测输出为准）。
2. **面试频率变高时**：把卡壳点整理成新文档，或补充到 `docs/interview/agentguide-rag-interview-mapping.md`，不无限堆进本文件。
3. **数字变化时**：先改 `ROADMAP.md`（唯一事实源），本指南只引用不改造。
4. **投递方向变了**：本指南聚焦「高级 AI 应用/Agent 开发」岗；若转前端负责人/前端专家岗，主线换成 AG-UI/SSE、流式状态、跨岗位协作（见 `docs/interview/README.md` 第五节）。
5. **本文件可丢给 AI 优化**：把整个文件内容贴给 DeepSeek/Claude，让它按你的最新面试记录重构第 6 节，或生成针对某公司的模拟问答。
