# 开源项目参考能力归档

> 记录 Dify、RAGFlow、AutoGPT、MetaGPT、CrewAI、AutoGen 对当前项目的可参考能力、实际融合结果和明确边界。
>
> 当前项目：企业智能知识库与游戏官网／活动营销 Agentic RAG 平台。
>
> 记录原则：只记录已经结合当前 NestJS + React + LangGraph.js + Milvus + Elasticsearch／BM25 + Redis + Neo4j + MCP 架构落地，或明确标记为待生产接入的内容，不把外部项目能力直接照搬成“已实现”。

## 一、总体结论

当前项目没有引入上述项目的第二套运行时，而是吸收其产品设计和工程思想，统一落到现有链路：

```text
Dify              → 平台治理、模型／工具／工作流版本、评测集、运营看板
RAGFlow           → 知识库治理、解析切块、混合检索、检索调试、引用追溯
AutoGPT           → Agent Run、Action、成本、审批、重试、模板复用、运行中心
MetaGPT           → 角色 SOP、结构化交接、Artifact 依赖、冲突决策、项目回放
CrewAI            → Task、Process、Sequential／Hierarchical／Conditional 编排
AutoGen           → 运行事件、消息流、Agent as Tool、工具预算、多 Agent 指标
                          ↓
             LangGraph + Redis Checkpointer + Agent Ops
                          ↓
          RAG 问答、方案生成、运营审计、持续回归闭环
```

### 已形成的统一闭环

1. 用户提问或管理员启动产研运工作流。
2. 系统根据 Simple／Auto／Agentic 路由执行检索、生成或多 Agent 编排。
3. 每个 Agent、Task、Tool、Artifact、交接消息和审批动作都有结构化记录。
4. 低质量回答可以提交 Bad Case，经过审核、回灌、重新召回和回归验证。
5. Agent Ops 可以查看运行中心、调用链路、事件流、任务看板、Artifact、冲突决策和项目回放。
6. LangFuse 记录 Trace／Generation，Prometheus 记录运行指标，平台治理负责模型、工具、知识库和评测集配置。

### 当前检索链路

```text
文档／URL／Obsidian／官方资料
  → 解析与清洗
  → Parent／Child 切块
  → Embedding + BM25／ES 索引
  → 权限和知识版本过滤
  → 关键词召回 + 语义召回 + KG／图谱扩展
  → RRF 融合
  → Rerank 重排
  → 引用校验与低相关拒答
  → Prompt 上下文
  → 生成回答或结构化方案
```

### 当前项目没有照搬的内容

- 不新增第二套解析、切块和向量数据库。
- 不把 RAGFlow 的部署集群能力写成当前本地项目已经具备的生产高可用。
- 真实业务文档、真实长期效果和真实 SLA 仍需要业务数据验收。

### 当前项目没有照搬的内容

- 不引入 AutoGen Runtime，继续使用 LangGraph。
- 不使用自由群聊替代结构化任务和审批门禁。
- 当前事件序号适合本地和单实例，生产多副本需要数据库序列或原子计数器。
- AutoGen 官方仓库目前处于维护模式，生产级新项目应评估 Microsoft Agent Framework；本项目只吸收可迁移的事件、消息、工具和评测思想。

## 九、统一状态流转

```text
用户问题／管理员工作流
  → 路由：simple／auto／agentic
  → Run 创建：步骤、工具、委派、成本预算
  → 检索：关键词、语义、图谱、融合、重排、权限过滤
  → Agent Task：角色、依赖、SOP、交接、Artifact
  → Tool：MCP／内部工具、风险检查、动作审计
  → 审批：高风险动作、产物、冲突和 Bad Case
  → 回答／结构化交付物
  → LangFuse Trace + Prometheus 指标 + 运行事件
  → 用户反馈／Bad Case
  → 审核 → 回灌 → 重新召回 → 评测回归
```

## 十一、面试表达口径

可以概括为：

> 我没有把多个 Agent 框架直接堆进项目，而是分别吸收它们解决的问题：用 Dify 的平台治理思想管理模型、工具、工作流和评测；用 RAGFlow 的知识库和检索工程思想完善父子切块、混合检索、重排和引用追溯；用 AutoGPT 的 Run、Action、成本和审批完善运行中心；用 MetaGPT 的角色 SOP、结构化交接和产物依赖固化协作；用 CrewAI 的 Task／Process 分层管理任务和流程；用 AutoGen 的事件驱动、Agent as Tool、工具预算和多 Agent 评测完善运行控制面。执行引擎仍统一使用 LangGraph，状态恢复使用 Redis Checkpointer，工具接入使用 MCP，观测使用 LangFuse 和 Prometheus，避免引入重复 Runtime。
