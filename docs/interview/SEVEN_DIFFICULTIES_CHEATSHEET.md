# Agent／RAG 七个难点面试速查卡

更新时间：2026-08-03

## 一句话总纲

我做的不是一个接上大模型的聊天框，而是一套面向游戏官网和活动产研运的协作 Agent 平台：让任务能拆、岗位能协作、知识能检索、结论有证据、过程可恢复、结果可评测、错误能反哺。

## 回答任何技术题的五句话

1. **背景**：业务为什么需要它，原方案出了什么问题。
2. **对比**：我比较了哪几种方案，各自优缺点是什么。
3. **选择**：我最后选什么，为什么适合当前业务，不说“因为流行”。
4. **落地**：讲清数据流、状态、失败处理和关键代码边界。
5. **效果**：用指标、测试和真实边界收尾，不编造收益。

## 高频题核心答案

### RAG 召回怎样评测

先把检索和生成分开。检索看 Recall@K、Precision@K、MRR、nDCG、首个正确证据排名、来源覆盖、权限过滤正确率和延迟；生成看事实正确率、证据覆盖率、引用忠实度、拒答正确率。再按中文别名、数字时间、跨文档、多跳、无答案和权限场景分桶，否则平均分会掩盖问题。

### Agent 死循环怎样处理

先限制，再识别，再恢复：限制最大步数、总耗时、工具次数和 token；对连续相同节点、相同工具参数、状态无变化做重复检测；工具超时使用熔断和降级；状态通过 Checkpointer 保存，失败后从节点恢复；最后把轨迹纳入回归集，避免同类循环再次上线。

### Agent、Chatbot、Skill、Tool 的关系

Chatbot 主要是输入到回复；Agent 有目标、状态、决策、工具和停止条件。Tool 是可调用的原子能力，有明确 schema；Skill 是可复用的任务方法，负责何时选什么工具、怎样组合和验收；Agent 根据状态选择 Skill 或 Tool，并对执行结果继续决策。

### 为什么加 Reranker

第一阶段召回追求“不漏”，会混入语义相近但不能回答的问题；Reranker 联合阅读 query 和候选块，做更精细的相关性判断，把真正能支撑答案的证据排到前面。代价是延迟和费用，所以只重排较小候选集，并准备超时降级。

## 不能说错

- 模拟评测 100% 不等于真实业务 100%，只能证明工程路径和门禁成立。
- GraphRAG 不会天然提高所有问题，只适合实体关系、多跳和跨文档场景。
- Reranker 改善排序，不负责弥补第一阶段完全没召回的证据。
- 长期记忆不是保存全部聊天，而是带来源、时间和作用域的可检索事实。
- 多 Agent 不是越多越好；职责、上下文和失败边界清楚时才拆。
- 审批不是每个节点必经，只有指定岗位或达到风险阈值才暂停。
