# Task Agentic 岗位产物验收标准

> 版本：2026-09-15。本文用来说明六个岗位交付什么、什么情况下算通过，以及自动模式如何验收。文中“当前已实现”和“待补齐”分开描述，不把设计目标当成现成功能。

## 一句话先记住

每个岗位都要交一份能被下游使用的 Artifact。系统先检查格式、依赖和证据，再决定是否进入下一个岗位；自动模式不等于不验收，只是不等待人工点击。

## 一、所有岗位都要过的四道门

| 检查项 | 通俗解释 | 不通过时 |
| --- | --- | --- |
| 结构完整 | 必须有岗位结论、交付内容、问题、风险和 Schema，不能只返回几句描述 | 标记为待修订，不解锁下游 |
| 上游最新 | 不能继续使用已经被驳回或标记过期的上游产物 | 标记 `stale`，要求重新生成 |
| 证据可靠 | 事实性结论必须带当前检索证据，不能自己编一个引用 | 标记 `pending_confirmation` |
| 岗位边界 | 只能做本岗位的决定，不能替其他岗位拍板 | 退回当前岗位修订 |

产物还要满足：`deliverables` 不为空，所有声明的证据状态为 `supported`，并且通过结构化 Schema 校验。满足这些条件后，产物才会被标记为可以继续流转。

## 二、六个岗位分别验收什么

### 1. 产品岗位

交付：需求 Brief、用户故事、业务规则、范围边界和验收清单。

通俗验收：别人只看这份产物，就能知道“给谁做、解决什么问题、做哪些、不做哪些、什么结果算完成”。

必须检查：目标、用户、流程、规则、地区／版本差异、异常情况、验收口径和待确认项。

### 2. 设计岗位

交付：页面结构、交互流程、视觉约束和状态说明。

通俗验收：用户从进入页面到完成操作，每一步怎么走都说得清，正常、加载、空数据、错误和成功状态不能缺。

必须检查：页面层级、交互闭环、尺寸规范、多端适配、多语言和无障碍要求。

### 3. 后端岗位

交付：API Contract、数据模型、权限规则和服务约束。

通俗验收：前端知道怎么调用，后端知道怎么校验，出现重复请求、异常请求或并发请求时不会重复发奖、重复写入或越权。

必须检查：请求／响应字段、错误码、权限、幂等、并发、资格校验、数据一致性、补偿和可观测性。

### 4. 前端岗位

交付：页面实现、组件结构、接口接入和埋点方案。

通俗验收：页面能运行，接口能接上，用户看得到加载、空态、错误和成功反馈，关键行为能被统计。

必须检查：组件拆分、状态管理、接口映射、异常降级、性能、埋点和页面构建入口。

### 5. 测试岗位

交付：测试计划、测试用例、验收结果和风险清单。

通俗验收：不仅测试“正常能不能用”，还要测试错误输入、重复操作、权限、边界、兼容和恢复。

必须检查：前置条件、输入输出、主流程、异常流程、边界值、兼容性、回归结果和上线门禁。当前系统的测试兜底 Schema 至少包含“主流程可完成”检查，真实项目用例仍需补齐。

### 6. 运营岗位

交付：发布计划、活动配置、灰度方案、监控指标、应急预案和复盘指标。

通俗验收：上线前知道怎么发，上线后知道看什么，出问题知道什么时候停、怎么回滚、谁负责。

必须检查：发布时间、配置项、灰度范围、核心指标、告警阈值、回滚条件、客服口径和复盘方式。

## 三、岗位之间怎么接力

```text
产品 → 设计、后端（并行）→ 前端 → 测试 → 运营 → 交付
```

- 设计和后端都依赖产品，二者可以并行。
- 前端要同时依赖设计和后端。
- 测试要等产品、设计、前端、后端的产物齐全。
- 运营要等产品、设计、前端、后端和测试全部完成。
- 任一岗位被驳回，只重跑被驳回岗位及受影响的下游，不从头重跑整条流程。

## 四、自动模式怎么验收

自动模式的实际步骤是：

```text
生成 Artifact
  ↓
Schema 校验、证据校验、上游版本校验、风险检查
  ↓
通过：自动解锁下游
不通过：标记 revision_required，等待修订
```

自动模式可以自动通过的情况：

- 产物字段完整，Schema 校验通过。
- 上游产物是当前有效版本。
- 事实性声明都有可用证据。
- 风险等级在自动放行范围内。
- 代码或文档的静态检查通过。

仍然必须人工审批的情况：

- 生产发布、灰度扩大或回滚。
- 权限、资损、奖励、支付等高风险变更。
- 数据删除、隐私、法务或合规问题。
- 自动检查结果不确定，或产物包含 `pending_confirmation`。

## 五、当前代码已经做到什么

当前代码已经具备：

- 六个岗位的 DAG 依赖和批次执行。
- 结构化 Artifact 和低代码 Schema 校验。
- 事实声明与 RAG 证据绑定。
- 驳回后 `revision_required`、旧产物 `rejected`、下游 `stale` 和局部重跑。
- 按 `approvalMode` 和风险等级决定是否进入人工审批。

当前还不能说已经完全做到：

- 六个岗位都有可执行的完整自动验收用例。
- 前端真实浏览器验收、后端真实接口回归和生产发布演练全部自动完成。
- 企业级安全、法务、灰度和回滚平台已接通。

因此，面试或人工审核时应说：

> 我们已经实现了岗位 DAG、结构化 Artifact、证据绑定、Schema 校验、驳回修订和风险审批。自动模式会先做结构、依赖、证据和风险门禁；高风险动作仍保留人工审批。具体业务的完整测试用例和生产发布验收，需要接入真实项目后补齐。
