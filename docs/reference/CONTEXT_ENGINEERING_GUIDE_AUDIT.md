## 交叉结论
1. **工作流审批、纠偏和恢复范围**：BullMQ 审批重试绑定原检查点，后续批次不会误用旧批准；驳回决定先持久化，Task/Artifact 副作用失败可续写，revision_required 后的事件/运行记录/索引收尾可按同一决定补齐。通用 Run 状态和 `run.updated` 事件不是原子写入，但驳回收尾重试会按 Run 和完整结果载荷查找事件，缺失时补发。工作流跨 Worker 取消通过 Redis 标记与 500ms 检查实现，但尚未在真实 Redis/Worker 环境做故障注入。另有两个不同能力边界：通用 AgentLoop.resume 没有调用入口；Run Center retry 创建新 Run 并完整重跑，不续接失败 Run 的原节点。旧队列任务缺少检查点身份时按 fail-closed 处理；其他修订运行事件去重只检查最近 500 条。Chat Agentic 人工审批有独立 LangGraph Command.resume。
2. **评测能力与业务证据分开**：Agent 轨迹评分器读取人工整理的真实运行事件包，检查事件顺序、载荷和禁止事件；多轮上下文评测器比较完整历史、最近 N 轮、无历史及服务端持久会话，可核验真实压缩事件和压缩后的追问命中。二者需要真实、脱敏、已审核的数据；前者不评答案质量，后者不动态模拟用户，关键词命中也不是语义保真结论。Langfuse 合成 Experiment 只测 trace/provider 序列化契约，不测 RAG 答案质量。当前无真实业务评测集和运行报告。
3. **Skill 正文已进上下文**：Chat 选中的本地项目 Skill 正文进入模型系统上下文，并与记忆/摘要共享预算；不足时整条 Skill 丢弃，事件记录注入与丢弃名称。Skill 不能覆盖系统安全策略、权限边界或用户本轮要求。
4. **“三层压缩”指策略选择，不是三层记忆**：供应商/模型选基线 → Hybrid 按对话特征选择 → 置信度低时比较 middle/oldest。两种结果按 Token 减少与消息保留的 0.6/0.4 权重打分；触发/目标和 Token 均为估算启发式。摘要文字有界；稀疏压缩 ID 达到 128 个时，强制压缩最旧连续前缀并推进水位线，PostgreSQL 原文不删，近期校验按页读取。仍没有基于真实会话的语义保真评测。PostgreSQL 原文、持久摘要与 Redis 缓存、Mem0 用户/会话记忆各有职责，不能混称压缩层。
5. **模型预算覆盖请求与主要后台任务**：主问答、规划、Agentic 判断、记忆摘要/分类、工作流岗位和产物编辑有业务预算预检或裁剪；`LlmProvider` 汇总 HTTP 请求与主要 BullMQ 任务内的调用次数、估算输入及最大输出预留，并对 invoke/stream/transform/batch 计数。异步输入流内容量难以预估，独立视觉／Embedding SDK 不在累计预算的准确统计范围；数字是上限估算，不是精确账单。
6. **记忆过期与来源指针边界**：明确绝对到期日且适用于整批用户事实时会写过期元数据并在检索时过滤；记忆附有来源会话、用户/助手消息 ID 和用户消息时间，但它们只是整次记忆写入的来源指针，不是每条抽取事实的独立证据链。云端 Mem0 请求 latestOnly；本地 REST 不支持，事实级冲突裁决与周期归纳仍未实现。
7. **文章对应的是不同能力边界**：Browser Use、KAIROS 常驻循环、双持久数据库、TSV、HyDE 和父块检索仍不应仅凭文章接入；Bash、项目内 Grep/Glob 与 Write/Edit 已在 OpenSandbox workspace Agent 的受限项目工作区部分适用，不等于通用宿主机工具，命令/路径限制与人工审批仍有缺口。MCP 与模型原生工具评测对应的上游文件为空，不能据此推导规格。
