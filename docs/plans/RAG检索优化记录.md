# RAG 检索优化记录

## 问题

历史会话和低相关片段会污染回答；所有问题都走同一套检索链路，导致简单事实被误判为“资料不足”。

## 已完成

- 共享语义预路由：区分系统能力、稳定事实、项目知识、实时信息和任务执行。
- 稳定通用事实直接回答；项目、私有和实时问题进入检索。
- 历史上下文标记为非事实依据，客观事实问题隔离历史与记忆。
- Hybrid、RRF、父子上下文、Rerank、权限／版本过滤和充分性门禁继续作为检索底座。
- 按 Query 对长片段做句级去噪压缩，减少无关上下文。
- Query 独立化重写接入 Agentic 检索；常见技术术语与别名统一规范化。
- 充分性阈值按 lookup／procedure／comparison／generation 动态调整。
- 候选上下文增加轻量 MMR（分词相关性＋冗余惩罚），减少重复片段。
- 入库为每个 chunk 生成假设性问题，写入 PostgreSQL 与 Elasticsearch，并同步扩展本地 BM25 召回；命中后仍只把原文作为回答证据。
- 增加动态多义词消歧：由路由模型根据当前问题生成候选语义；低置信度先澄清，模型失败时保守放行，不使用硬编码词表；不允许 Hypothetical Questions 或历史结果单独决定词义。
- 对仅含实体名的查询，由语义路由模型判断主流指代；存在主流含义时直接解释，只有多个语义同等合理时才澄清，不因输入短而拒答。
- 语义路由模型判断定义、歧义和检索必要性；路由窗口调整为 20 秒，将语义结论作为正确性门槛，避免因抢时延超时而退化为错误检索。
- 语义路由改用统一 LLM Provider 的纯文本 JSON 输出并本地校验；允许省略 ambiguity 的非必要字段，避免有效语义结果因 schema 过严而误降级。
