# 历史上下文事实污染与模型切换优化方案

## 问题

历史会话、短期记忆、长期记忆和对话向量检索结果被直接拼接到模型上下文。用户或旧模型曾经说过的错误内容，例如「1+1 等于 5」「React 是一种动物」或「当前模型是 DeepSeek」，会被新一轮模型误认为事实，导致切换模型后出现身份冲突和连续错误回答。

根因不是某个模型“记错”，而是上下文没有区分来源、用途和可信度；历史消息还曾以高优先级消息注入，放大了污染。

## 目标

- 历史会话只负责语义连续性、指代消解和任务状态，不定义客观事实。
- 技术定义、数学、科学、模型身份、版本和实时信息优先使用运行时配置、已验证知识或可靠工具。
- 用户偏好、项目状态和客观知识分层存储，避免整段聊天直接进入长期记忆或 RAG。
- 模型切换后不继承旧模型的身份自述。

## 已实施方案

1. 新增统一上下文策略，明确“历史消息和用户陈述可能错误，不能作为客观事实依据”。
2. 对「是什么」「定义」「等于几」及基础算式等客观事实问题，禁用相关历史问答向量召回，并清空短期历史注入。
3. 对非事实追问保留有限历史，但历史向量结果改标为“仅作语义线索，非事实依据”。
4. 普通 Chat、AG-UI 流式问答和 Chat SSE 统一注入同一套策略，避免不同入口行为不一致。
5. Mem0 记忆上下文增加范围和可信度说明：用户偏好、项目状态可参考，但不能覆盖已验证客观事实。

## 后续演进

- 已新增共享 `QueryIntentRouter`：三条问答链路在检索前仅依据当前问题做结构化语义分类；关键词仅作为分类模型超时或不可用时的保守回退，不作为主路由依据。
- 为记忆增加 `type`、`confidence`、`scope`、`source` 字段，默认把用户陈述标记为 `user_claim`，不参与事实回答。
- 只将 `preference`、`project_state` 和 `verified_fact` 纳入可检索上下文；原始聊天保留用于审计，不直接向量化。
- 增加错误历史、模型切换、过期版本和用户纠错的回归评测集。

## 验收标准

- 历史包含「1+1=5」时，询问「1+1 等于几」不再召回该历史，回答为正确结果。
- 历史包含「React 是动物」时，询问「React 是什么」不再受其影响。
- 切换 DeepSeek／GLM 后，模型身份回答只读取当前运行时模型配置。
- 普通追问仍能使用最近历史完成指代和任务连续性。
