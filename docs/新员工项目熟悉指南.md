# 新员工 RAG 服务熟悉指南（1 天版）

> **学习范围**：以 `apps/rag-api` 为主，先弄清 RAG 服务做什么、关键请求如何流转。前端和 Admin API 只看它们怎样把请求送入 RAG 服务，不要求一天内熟悉整个平台的每个子系统。

## 一天的目标

一天内先建立项目地图，能用自己的话讲清楚：

1. 用户的问题从哪个页面进入，经过哪些服务，最后在哪里生成和保存答案。
2. 上传的文件如何变成可检索的资料，主要索引分别做什么。
3. 一个问题或入库任务出错时，应该先看哪个模块、哪类运行记录。

不需要一天读完所有文件。先沿着真实请求走通两条主线：**问答**和**文档入库**。

| `packages`       | RAG CLI、MCP Server 等可复用入口。                              |

最先读[系统架构](architecture/ARCHITECTURE.md)、[功能步骤流程](interview/功能步骤流程.md)、[项目说明](../README.md)和[当前进度](../ROADMAP.md)。架构图说明模块边界，流程文档说明真实调用顺序，ROADMAP 说明已验证和待验证的部分。

## RAG 服务功能地图

RAG API 在 `apps/rag-api`，`main.ts` 统一设置 `/api/v1` 前缀。读代码时按“入口控制器 → 编排服务 → Provider/存储”的方向追，不要从上百个模块目录开始逐个翻。

| 功能 | 服务负责什么 | 优先阅读入口 |
| --- | --- | --- |
| 身份与数据范围 | 验证用户或内部服务身份，把租户、部门和资源权限带入后续检索与读写。 | `src/common/guards/`、`src/modules/auth/`、`src/modules/iam/`、`src/rag/retrieval/rag-chunk-policy.service.ts` |
| 知识入库 | 接收文件，解析、审核、切片，保存业务记录并协调各检索索引。 | `src/modules/document/`、`src/providers/object-storage/`、`src/providers/db/`、`src/providers/elasticsearch/`、`src/providers/vector-store/` |
| 问答与 RAG 检索 | 接收问题和会话上下文，生成查询计划，按策略找证据，再生成并校验回答。 | `src/modules/chat/`、`src/rag/planning/`、`src/rag/retrieval/`、`src/rag/agentic/` |
| Agent、工具与长任务 | 在复杂问题或任务中编排模型、检索、受控工具、审批、运行状态和恢复。 | `src/rag/agents/`、`src/tools/`、`src/modules/agent-runs/`、`src/modules/agent-runtime/`、`src/modules/workflow/` |
| 会话与记忆 | 保存会话消息和摘要；按策略读取跨会话记忆，不能把记忆与原始对话混为一类。 | `src/modules/chat/`、`src/modules/memory/` |
| 管理与质量运营 | 提供 RAG 内部管理接口、索引修复、评测、运行追踪和指标。内部管理接口由 Admin API 使用服务令牌调用。 | `src/modules/rag-admin/`、`src/modules/agent-evals/`、`src/modules/tracing/`、`src/modules/metrics/` |
| 图片、语音等多模态能力 | 按需解析、索引或查询图片与语音；属于扩展链路，先熟悉核心问答和文档链路后再看。 | `src/modules/image-index/`、`src/modules/speech/`、`src/providers/vision/` |

常见入口可先记为：`/api/v1/chat` 是聊天入口，`/api/v1/documents` 是用户文档入口，`/api/v1/rag/admin` 是供管理服务调用的内部接口。实际子路径以控制器上的路由装饰器为准；`/api/v1` 前缀和版本由 [main.ts](../apps/rag-api/src/main.ts) 统一设置。

## 主线一：一次 QA Ops 问答

实际流式问答大致按这条路径执行：

```text
QA Ops 页面
→ Admin API 校验管理权限
→ RagClient 带服务令牌转发请求，并映射管理员身份
→ RAG API 校验服务令牌、身份和租户
→ AguiService 负责会话、附件、事件和产物适配
→ ChatService 准备历史、记忆和 QueryPlan
→ AgenticRagService 选择快速回答或深度状态图
→ RagRetrievalService 找证据、过滤、合并和排序
→ 生成答案、保存结果、把事件推回页面
```

按这个顺序看文件：

1. [QA Ops 页面入口](../apps/admin-web/src/pages/qa-ops/index.tsx)、[页面请求服务](../apps/admin-web/src/pages/qa-ops/service.ts)
2. [Admin API QA Ops 控制器](../apps/admin-api/src/modules/qa-ops/qa-ops.controller.ts)、[RAG 客户端请求](../apps/admin-api/src/modules/rag-client/rag-client-qa.ts)
3. [RAG AG-UI 控制器](../apps/rag-api/src/modules/agui/agui.controller.ts)、[AguiService](../apps/rag-api/src/modules/agui/agui.service.ts)
4. [ChatService](../apps/rag-api/src/modules/chat/chat.service.ts)、[QueryPlannerService](../apps/rag-api/src/rag/planning/query-planner.service.ts)
5. [AgenticRagExecution](../apps/rag-api/src/rag/agentic/agentic-rag.execution.ts)、[AgenticRagService 状态图](../apps/rag-api/src/rag/agentic/agentic-rag.service.ts)
6. [统一检索服务](../apps/rag-api/src/rag/retrieval/rag-retrieval.service.ts)

注意两点：

- 管理端的流式请求经 Admin API 转发到 RAG API 的 `/agui/admin/stream`。会话列表等管理接口走 QA Ops 相关控制器；不要把两类入口混成一个。
- `simple`、`auto`、`agentic` 最终都由 `ChatService` 交给 `AgenticRagService`。`auto` 根据 QueryPlan 和证据情况选择快速路径或深度状态图；并不是 ChatService 内有三套互不相关的实现。

读完后，找一个问题沿调用链确认：用户身份怎么传、QueryPlan 从哪里来、检索结果如何成为回答证据、事件怎样回到页面、会话结果在哪里保存。

## 主线二：一份文档如何进入检索

```text
上传请求
→ 文件解析成正文
→ 租户权限和内容安全检查
→ 结构化切片并补充来源、版本等信息
→ PostgreSQL 保存业务记录和切片，同时协调写入 BM25、Elasticsearch、Milvus
→ 检索时按权限、生命周期和范围筛选
```

建议从这些位置跟：

1. [文档上传控制器](../apps/rag-api/src/modules/document/document.controller.ts)：区分同步上传和异步上传；异步入口会先保存原文件，再由任务处理。
2. [Obsidian 入库适配](../apps/rag-api/src/modules/document/obsidian-ingest.service.ts)：处理去重和可选的 Obsidian 来源笔记，再调用统一文档入库。
3. [DocumentService](../apps/rag-api/src/modules/document/document.service.ts) 与 [DocumentUploadWorkflow](../apps/rag-api/src/modules/document/document.service.upload-workflow.ts)：检查权限、做质量/安全门禁、切片、建元数据并推进任务状态。
4. [索引协调器](../apps/rag-api/src/modules/document/document-index-coordinator.service.ts)：把同一批切片写入不同索引，汇报必需索引失败。
5. [RAG 管理与索引修复](../apps/rag-api/src/modules/rag-admin/rag-admin.service.indexing.ts)：查看索引审计和重建流程。

先记住存储职责：PostgreSQL 保存文档和切片等业务数据；Milvus 用于向量召回；BM25 和 Elasticsearch 提供关键词/全文召回；Redis 支持队列和短期运行状态；Neo4j 是可选图索引。文件原件由对象存储管理。**这些索引不是彼此的备份，写入是否成功要看任务状态和索引审计。**

## 按职责定位源码

多数业务入口负责组合依赖和推进流程，具体步骤由同目录的工作流或 support 文件承担。沿调用链阅读时，可以从入口进入，再按需要打开对应职责文件：

- **文档入库**：[DocumentService](../apps/rag-api/src/modules/document/document.service.ts) 组合上传、分块和恢复流程；具体步骤见 [上传工作流](../apps/rag-api/src/modules/document/document.service.upload-workflow.ts)、[分块工作流](../apps/rag-api/src/modules/document/document.service.chunk-workflow.ts) 和 [恢复工作流](../apps/rag-api/src/modules/document/document.service.recovery-workflow.ts)。索引写入由 [DocumentIndexCoordinator](../apps/rag-api/src/modules/document/document-index-coordinator.service.ts) 负责。
- **Agentic RAG**：[AgenticRagService](../apps/rag-api/src/rag/agentic/agentic-rag.service.ts) 初始化状态图并组合执行能力；计划、检索、执行、恢复和状态分别见 [planning](../apps/rag-api/src/rag/agentic/agentic-rag.planning.ts)、[retrieval](../apps/rag-api/src/rag/agentic/agentic-rag.retrieval.ts)、[execution](../apps/rag-api/src/rag/agentic/agentic-rag.execution.ts)、[resume](../apps/rag-api/src/rag/agentic/agentic-rag.resume.ts) 和 [state](../apps/rag-api/src/rag/agentic/agentic-rag.state.ts)。
- **记忆**：[MemoryService](../apps/rag-api/src/modules/memory/memory.service.ts) 负责记忆查询与持久化；[memory-context.support.ts](../apps/rag-api/src/modules/memory/memory-context.support.ts) 放上下文格式化和筛选纯函数；[MemoryConsolidationService](../apps/rag-api/src/modules/memory/memory-consolidation.service.ts) 独立处理长期记忆归纳草案和审核。
- **管理端工作流详情**：[页面控制器](../apps/admin-web/src/pages/agent-ops/workflow-detail/workflow-detail-controller.tsx) 组合页面数据与产物操作；[工作区 Hook](../apps/admin-web/src/pages/agent-ops/workflow-detail/workflow-detail-workspace-controller.ts) 管理开发工作区状态和操作；视图与产物区块分别在 [详情视图](../apps/admin-web/src/pages/agent-ops/workflow-detail/workflow-detail-view.tsx) 和 [产物区块](../apps/admin-web/src/pages/agent-ops/workflow-detail/workflow-detail-artifact-sections.tsx)。

更完整的运行和上下文说明见[Agent Runtime](AGENT_RUNTIME.md)、[上下文工程](CONTEXT_ENGINEERING.md)和[运维说明](OPERATIONS.md)。

## 开发环境入口

根目录的 `README.md` 有 Docker 和 workspace 启动命令。常用服务入口：

- QA Ops：`http://localhost:8000/qa-ops`
- Admin API 文档：`http://localhost:3001/docs`
- RAG API readiness：`http://localhost:3000/api/v1/health/ready`
- 用户前台：`http://localhost:5173/`
- Langfuse：`http://localhost:3002/`

本地配置可能关闭 Admin API 自身的数据库或队列，并使用内存模式；RAG API 的 PostgreSQL/Redis 是另一套运行依赖。排查持久化问题时先看启动日志和[运维说明](../docs/OPERATIONS.md)，不要仅凭页面能打开就认定所有服务都已连上。
