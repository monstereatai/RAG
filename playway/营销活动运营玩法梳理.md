# 游戏营销活动运营玩法梳理

> 整理范围：`playway/` 目录中的 9 张组件库截图、`playway/README.md`、组件清单和运行时活动模板。
>
> 说明：截图中的分类和组件名称来自 OCR；组件 ID 是 RAG 项目为 `pageSchema` 约定的标准化命名，原平台内部 ID 仍需以真实系统为准。

## 一、整体结论

Playway 不是单纯的页面搭建工具，而是围绕游戏用户增长和运营转化的低代码活动中台。当前资料明确沉淀了 4 类标准活动模板、14 个组件分类和 96 个活动组件，其中包括 12 个有计数面板分类，以及通用组件、页面框架 2 个整理分组：

- 新服预约活动：在新服务器开放前完成预约、预创角和奖励转化。
- 私域拉新活动：通过社群、公众号和邀请裂变获取可归因的新用户。
- 游戏促活活动：通过登录、分享、充值、积分和抽奖形成日常活跃循环。
- 游戏回流活动：识别流失用户，通过回归任务和奖励促成再次登录。

## 二、四类标准活动与运营玩法

### 1. 新服预约活动

#### 运营目标

开服前积累预约用户，推动预创角、预充值、角色绑定和组队，并通过预约里程碑和抽卡奖励提升转化。

#### 典型链路

```text
进入预约页 → 查看开服时间 → 登录／绑定角色 → 立即预约
→ 预创角／预充值／组队 → 达成预约里程碑 → 预约抽卡 → 下载游戏等待开服
```

#### 核心组件

- 必选：Banner、立即预约、开服时间、活动规则。
- 可选：预约里程碑、预约抽卡、抽卡次数、预充值、预创角、组队、英雄池、预约场景角色绑定。

#### 关键数据与验收

- 接口：活动信息、预约状态、预约提交。
- 埋点：活动页浏览、预约提交。
- 活动关闭后不可预约；同一账号重复预约必须幂等。
- 预创角、预充值和奖励资格必须以后端结果为准。
- 涉及角色绑定、预充值或抽卡时，需要增加资格校验和资损校验。

### 2. 私域拉新活动

#### 运营目标

把社群和公众号流量转化为新用户，通过邀请海报、邀请关系、红包或抽奖奖励形成裂变闭环。

#### 典型链路

```text
进入活动页 → 加入社群／绑定微信 → 生成邀请海报
→ 分享给好友 → 服务端记录邀请关系 → 达成邀请目标
→ 发放红包／积分礼包／抽奖机会 → 查看邀请记录和奖励
```

#### 核心组件

- 必选：Banner、社群链接、邀请好友、邀请好友海报。
- 可选：邀请进度条、邀请记录、微信消息订阅、赏金红包、宫格抽奖、积分礼包、社群弹层。

#### 关键数据与验收

- 接口：活动信息、邀请码、邀请统计。
- 埋点：活动页浏览、邀请分享、邀请完成。
- 邀请关系必须由服务端归因，不能信任前端传入的邀请人数。
- 重复设备、重复账号和异常频率必须进入反作弊分支。
- 奖励发放和邀请记录必须可追溯。
- 红包、积分礼包和抽奖组合时，需要防止套利和刷量。

### 3. 游戏促活活动

#### 运营目标

围绕存量玩家建立每日参与循环，通过登录、分享、充值、积分兑换、集卡、抽奖和排行榜提升活跃度。

#### 典型链路

```text
登录游戏 → 完成每日分享／每日充值 → 更新任务进度
→ 积分兑换／集卡／每日抽奖 → 转盘抽奖或排行榜竞争
→ 查看任务完成情况和奖励
```

#### 核心组件

- 必选：Banner、登录游戏、任务进度、每日分享。
- 可选：每日充值、积分兑换、集卡、每日抽奖、转盘抽奖、任务完成排行榜。

#### 关键数据与验收

- 接口：活动信息、任务状态、奖励配置。
- 埋点：活动页浏览、游戏登录完成、任务状态刷新。
- 每日任务要按自然日或活动时区正确重置。
- 任务状态刷新后必须与服务端一致。
- 积分兑换的库存、次数和重复领取必须由服务端约束。
- 充值任务必须校验支付回调，不能用前端成功状态发奖。

### 4. 游戏回流活动

#### 运营目标

识别符合条件的流失用户，通过登录游戏、红包、免费抽奖等回归奖励促成再次登录。

#### 典型链路

```text
触达流失用户 → 进入活动页 → 登录并校验回流资格
→ 登录游戏 → 完成回流任务 → 发放红包／抽奖奖励 → 查看奖励结果
```

#### 核心组件

- 必选：Banner、登录、登录游戏、完成活动提示。
- 可选：红包任务、随机红包、自由抽奖、我的奖励、实名认证、智齿客服。

#### 关键数据与验收

- 接口：活动信息、回流资格、任务状态。
- 埋点：活动页浏览、登录成功、游戏登录完成。
- 非回流用户不可领取回流专属奖励。
- 回流资格、奖励领取和过期时间必须可查询。
- 完成任务后必须展示明确的奖励结果。
- 红包和抽奖需要限制重复领取与账号批量套利。

## 三、运营玩法按阶段拆解

### 1. 预热与触达

- 主视觉 Banner、轮播图、开服时间、任务倒计时。
- 社群链接、社群弹层、邀请海报、二维码任务。
- 微信消息订阅、地区菜单、语言菜单、海外登录。
- 活动规则、说明、客服入口。

### 2. 用户进入与身份确认

- 登录、海外登录、实名认证。
- 游戏登录、绑定角色、预创角、绑定微信。
- 回流资格、预约资格和奖励资格校验。

### 3. 任务驱动与行为转化

- 跳转任务、每日分享、每日充值、商城充值。
- 邀请好友、邀请进度、入队任务、组队任务。
- 任务进度、任务进度条、任务倒计时、刷新任务状态。
- 预充值、积分兑换、二维码扫码、红包任务。

### 4. 奖励与刺激机制

- 宫格抽奖、转盘抽奖、自由抽奖、付费分层抽奖。
- 每日抽奖、累计充值抽奖、队伍满员抽奖。
- 赏金红包、随机红包、红包口令兑换、积分礼包。
- 预约抽卡、集卡、卡片赠送与收取。
- 浮动礼包、我的奖励、钱包余额和红包提现。

### 5. 社交与竞争

- 创建、加入和解散队伍。
- 队伍列表、队伍信息、队伍成员、队伍成员列表。
- 队伍积分、邀请组队、组队满员抽奖。
- 任务完成排行榜、代言人排行榜、中奖名单和中奖轮播。

### 6. 结果反馈与留存

- 完成活动提示、任务奖励、任务进度。
- 我的奖励列表／表格、红包提现记录、邀请记录。
- 集卡订阅消息、投票记录、剩余可投票数。
- 客服入口、活动规则和结果公示。

## 六、通用运营与风控清单

### 运营配置

- 活动时间、倒计时、开服时间和任务重置时区。
- 任务条件、完成次数、邀请人数、充值档位和奖励配置。
- 抽奖次数、奖池分层、中奖概率、库存和领取有效期。
- 社群链接、邀请海报、二维码、微信订阅和多语言内容。
- 活动规则、说明、客服、奖励展示和结果公示。

### 数据与埋点

- 页面浏览、登录成功、游戏登录完成。
- 预约提交、邀请分享、邀请完成。
- 任务完成、任务刷新、充值完成、抽奖参与。
- 奖励发放、积分兑换、红包提现、卡片赠送／收取。
- 排行榜变化、分享渠道和异常行为。

### 风控与合规

- 资格、身份、角色、回流状态和实名状态由服务端校验。
- 邀请关系、任务人数、任务完成和奖励发放需要服务端归因。
- 对重复账号、重复设备、异常频率、批量套利和刷量建立拦截分支。
- 充值、红包、提现、抽奖、库存和积分兑换都要保证幂等、可追溯和防资损。
- 活动关闭、过期或资格失效后，前端入口和接口都不得继续发奖。

## 七、对 CakeCode／RAG 活动 Schema 的启发

可以把活动建模为：

```text
活动类型 → 运营目标 → 页面框架 → 任务链路 → 奖励机制 → 用户身份／资格
        → 埋点事件 → 风控规则 → 验收结果
```

推荐在生成活动 Brief 或 `pageSchema` 时，先确定 4 类活动模板之一，再从对应的必选／可选组件中组装页面，最后补充接口、埋点、风控和验收规则。
