# Simple Karpathy Fast Path：游戏运营营销公开资料方案

- 版本：2026-08-11T15:07:30.108Z
- 适用链路：Simple
- 资料范围：中国 PC 端候选 Top50、页游候选 Top50的公开官网、活动、运营、营销和社区页面。
- 关键原则：网页快照是证据，项目模板是方法；没有页面证据的奖励数值、预算、概率、接口字段和内部策略必须回答“待确认”。

## 用户操作流程

1. 用户在 AI 智能问答选择 Simple，输入“某游戏官网活动有哪些页面模块”“某页游周年庆活动如何拆页面和埋点”等问题。
2. 系统将问题标准化，识别游戏名、平台、活动类型、运营／营销／官网／社区意图。
3. 系统优先检索 Karpathy 编译索引中的游戏资料卡，再补充 Milvus 语义召回、BM25／Elasticsearch 关键词召回和父子块上下文。
4. 系统做 RRF 融合（注：把多路检索结果按排名合并）、轻量重排和引用校验。
5. 资料充分时，模型按“已知事实／可复用方法／待确认项／来源”加工回答；不会原样复制网页。
6. 资料不足时，Simple 不自行编造，也不进入多 Agent 循环；返回低相关提示和需要补充的关键信息。

## 服务端数据与状态流程

1. 公开网页进入采集器，保存 URL、榜单口径、游戏名、公司、平台、抓取时间和 content hash（注：内容指纹，用于去重和更新判断）。
2. 页面转成 Markdown 快照，写入 PostgreSQL 文档记录，并经过现有异步文档队列。
3. 文档解析为父块、子块和 metadata（注：父块保留页面上下文，子块用于精确召回），同步到 Milvus、BM25／Elasticsearch、Karpathy 编译层和 Obsidian。
4. Simple 查询只走 Fast Path：query normalize → intent tags → Karpathy／Obsidian 高优先级命中 → Hybrid Search → RRF → Rerank → citation gate（注：引用门禁）→ 结构化生成。
5. 查询、命中来源、耗时、召回数量、引用覆盖率和最终状态写入 QueryLog，并上报 LangFuse Trace／Generation；Prometheus 采集延迟、错误、空召回和索引失败指标。
6. 网页更新时按 content hash 生成新版本，旧版本进入 superseded（注：被新版本替代）状态；删除或失效时同步清理各索引，避免旧活动污染新回答。

## Simple 输出契约

- 结论：只写公开资料明确支持的内容。
- 可复用拆解：页面模块、接口类别、埋点类别、风险和验收清单。
- 待确认项：活动时间、预算、奖励、概率、资格、真实接口和内部数据。
- 引用：至少给出来源页面 URL、游戏名和抓取时间。
- 拒答边界：没有证据时不把相似游戏的做法改写成目标游戏事实。

## 与 Auto／Agentic 的边界

- Simple：固定单轮检索，低延迟，适合查官网模块、公开活动和通用拆解。
- Auto：先执行 Simple；当检索充分性门禁不通过时，再升级 Agentic。
- Agentic：拆分复杂问题，按子问题反复检索、图谱扩展、必要时调用网络搜索，再生成结构化方案。
- 三条链路共用同一份公开资料版本、权限过滤、引用校验和 Bad Case 回归，不复制三套知识。
