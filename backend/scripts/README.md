# Smoke scripts

These scripts turn the remaining roadmap follow-ups into repeatable checks.
They print JSON summaries only and must not print API keys, bearer tokens, raw
audio, vectors, or full model responses.

Run from `backend/`.

- `npm run smoke:mcp`: loads `workspace/mcp-servers.yaml`, calls the local MCP smoke server tool.
- `npm run mcp:validate`: validates `workspace/mcp-servers.yaml` shape without starting any MCP server. Use `MCP_CONFIG_PATH=...` to check a business config.
- `npm run smoke:graph`: logs in, imports `eval/graph-smoke.seed.json`, checks schema and GraphRAG query.
- `npm run graph:import-business -- --dry-run`: validates `eval/graph-business.seed.example.json` or `GRAPH_BUSINESS_SEED=...` without calling the backend. Remove `-- --dry-run` to import into a running GraphRAG backend.
- `npm run smoke:speech`: calls backend TTS SSE, then sends the generated wav to backend ASR.
- `npm run smoke:speech:direct`: calls Tencent TTS and ASR directly without a running backend.
- `npm run smoke:external`: real Bocha, DashScope Rerank, and Qwen judge calls when keys exist; otherwise reports skipped checks.
- `npm run smoke:external:required`: same checks as `smoke:external`, but missing keys fail the run. Use this after Bocha/Rerank/Qwen keys are filled.
- `npm run smoke:milvus`: checks Milvus collection/schema/index metadata, loadCollection, load state, loading progress, SDK/server versions, and a bounded warmup search. Use this when first vector retrieval emits timeout warnings. A failing search with healthy/indexed/loaded metadata points to Milvus runtime/version/segment state rather than RAG answer logic.
- `npm run smoke:milvus:conversation-history`: read-only checks a repeated conversation-question group in `conversation_chunks_v2`, strongly counts it before and after `queryIterator`, and fetches the selected latest row. It prints counts only, never conversation IDs or content. It requires an existing repeated group in the bounded sample; raise `MILVUS_HISTORY_SMOKE_SAMPLE_LIMIT` if needed.
- `npm run smoke:vision-video`: validates the private multimodal dataset has image/audio/video files and audio/video transcript sidecars. Set `VISION_VIDEO_REQUIRE_PROVIDER=true` only when a real OCR/video provider key must be mandatory.
- `npm run smoke:redis-checkpointer`: verifies checkpoint storage can be read by a separate Node process.
- `npm run smoke:hybrid`: uploads fixed Chinese regression documents, checks debug retrieval, then deletes the uploaded docs.
- `npm run eval:rag:judge`: optional Qwen LLM-as-Judge check for claim support. It skips when `QWEN_API_KEY` is not set.
- `npm run eval:rag:langsmith`: runs the stable local RAG evaluation and writes a LangSmith-friendly JSON export to `.tmp/langsmith-rag-eval.json`. Set `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`, and `LANGSMITH_PROJECT` to let LangChain/DeepAgents calls emit LangSmith traces during the run. Set `LANGSMITH_UPLOAD=true` to upload Dataset/Experiment data through LangSmith REST API; add `LANGSMITH_UPLOAD_REQUIRED=true` only when upload failure should fail CI.
- `npm run evidence:business`: uploads the selected business dataset to the real backend, evaluates every configured chat mode, and writes redacted JSON/Markdown evidence to `.tmp/evidence/rag-business.*`.
- `ACCESS_TOKEN=*** npm run evidence:stability`: repeats the production workflow through the real HTTP API and separates workflow completion, model success, degradation, approval readiness, artifacts, evidence coverage, and P95.
- `npm run evidence:operations -- redis,milvus-bad-case`: runs a whitelisted operational smoke set and writes a redacted exercise report. Add exercise metadata through `OPERATIONS_EVIDENCE_*` when running a controlled game day.
- `npm run evidence:readiness`: combines business, stability, performance, operational, ADR, cross-team, production-scale, and incident evidence without promoting missing or simulated data to production claims.
- `npm run eval:rag:maturity`: local enterprise maturity score. It checks the four core standards, business eval coverage, smoke entrypoints, governance evidence, and explicit external blockers. Default threshold is `RAG_MATURITY_MIN_SCORE=90`; set `RAG_PRODUCTION_MATERIALS_CONFIRMED=true` only after production target/cert/backup inputs are confirmed, and set `RAG_MATURITY_REQUIRE_EXTERNAL=true` only when private business data and production materials must block the gate.
- `npm run eval:langfuse:generate`: generates the synthetic Langfuse observability contract dataset.
- `npm run eval:langfuse:check`: checks the generated Langfuse dataset is current.
- `npm run eval:langfuse:dataset`: builds the backend, then replays the Langfuse scenario dataset against a local mock ingestion endpoint. It validates trace/generation/span serialization, usage/cost fields, redaction, tool events, production workflow spans, scheduled analysis and disabled contracts without requiring cloud keys.
- `npm run perf:rag`: runs real simple/auto/agentic latency samples and writes `.tmp/evidence/rag-performance.{json,md}`. Use `PERF_RAG_PROFILE=local` for local engineering thresholds. Strict-profile cost checks read the run's `cost.estimated` event through the protected run-center endpoint; set `PERF_RAG_SERVICE_TOKEN` or `RAG_SERVICE_TOKEN`. This is estimated usage/cost, not billing. Run-center reads happen after each chat duration is recorded, so they do not inflate latency samples.
- `PERF_RAG_MODES=simple,auto,agentic PERF_RAG_CONCURRENCY=2|5|10 npm run perf:rag`: runs a selected mode/concurrency matrix. Use `PERF_RAG_OUTPUT=.tmp/evidence/load-<mode>-c<concurrency>.json` to keep each result.
- `docs/reference/LANGFUSE_OBSERVABILITY_TEST_MATRIX.md`: full Langfuse test matrix, scenario list and cloud acceptance checklist.
- `npm run eval:rag:project`: project-like evaluation. By default it runs Simple, Auto, and Agentic; `eval/project-simulated-business.dataset.json` is explicitly marked synthetic, so its score is regression evidence, not real-business validation. Set `PROJECT_EVAL_DATASET` to choose another dataset and `PROJECT_EVAL_REQUIRE_LIVE=true` to fail instead of skipping when the backend is unavailable.
- For same-question retrieval-profile comparison, set both `PROJECT_EVAL_PROFILE_A` and `PROJECT_EVAL_PROFILE_B` to different enabled profile keys, plus `PROJECT_EVAL_SERVICE_TOKEN` (or `RAG_SERVICE_TOKEN`) so the script can verify the selected profiles and their effective configs differ. The same optional service token lets the evaluator read each chat response's `runId` through the protected `run-center/:id` endpoint and collect its `cost.estimated` event. Reports include per-result and A/B token totals and estimated-cost deltas. `costUsd` is always reported as an estimate; the event's `source` distinguishes provider-reported token counts from estimated token counts. If no service token, run ID, or cost event is available, that result is marked unavailable and the user-JWT chat evaluation continues. Variant order alternates per query. The script assigns uploaded fixtures a unique `projectId` and passes that scope to every chat request, so both variants search the same evaluation documents without mixing in the login user's other project-scoped documents. For release A/B cost gating, only queries with cost estimates available for both variants count toward paired cost coverage and comparison. Use `PROJECT_EVAL_MODES=simple` for a focused retrieval comparison. This is an offline paired evaluation under the login user's ACL, not online traffic A/B; it has no confidence interval and latency is approximate.
- `npm run eval:rag:quality`: stable local gate. It always runs offline RAG eval, the 120-case business dataset check, and the local maturity gate. Set `EVAL_RAG_JUDGE_REQUIRED=true` to make Qwen LLM-as-Judge mandatory.
- `npm run eval:rag:release`: requires an explicit `PROJECT_EVAL_DATASET` whose metadata declares `synthetic: false`, `provenance.kind: "sanitized_real_business"`, `provenance.reviewed: true`, and a non-empty `provenance.sourceDescription`. The dataset needs at least 5 documents and 100 uniquely identified queries, including refusal and conflict cases; at least 20 queries (and at least 20% of the dataset) must be answerable. Every answerable query must set `requireCitation: true`, list existing `expectedDocIds` (or the compatible legacy `sourceDocumentIds`), and include `expectedClaims`; live evaluation fails a case when its references do not contain one of those documents. Release must run Simple, Auto, and Agentic, and each mode/profile plus its answerable subset must meet `PROJECT_EVAL_MIN_SCORE` (minimum 0.9), so refusal-heavy datasets cannot hide a weak answer path. It requires estimated-cost events for at least 90% of results in every mode/profile (`EVAL_RAG_MIN_COST_COVERAGE` may be raised, but not lowered below 0.9); configure `PROJECT_EVAL_SERVICE_TOKEN` or `RAG_SERVICE_TOKEN` for protected run-center reads. These values are estimated cost, not billing data. When comparing profiles, the gate also blocks a candidate regression in retrieval hit rate, MRR, or nDCG; the default allowed regression is 0 (`EVAL_RAG_MAX_RETRIEVAL_REGRESSION` can set a tolerance from 0 to 1). For release A/B comparisons, set `EVAL_RAG_MAX_COST_REGRESSION` and `EVAL_RAG_MAX_LATENCY_REGRESSION` to business-approved relative increases from 0 to 1; both are required. The gate compares estimated cost on the same paired queries (with at least the configured cost-coverage threshold available for both variants) and paired mean latency, and fails when a limit is missing or exceeded. Release thresholds cannot be lowered below 0.9, and the Judge must score every answerable case. It receives this run's answer and cited chunk text through stdin; the gate does not save that raw answer/evidence in a report or print it to the terminal. Only use sanitized data because those live answers and evidence are sent to the configured judge model. The gate checks declared provenance fields, not source authenticity; a human reviewer must verify them. Evaluation cleanup reuses the login token and returns failure if any uploaded document cannot be deleted.
- `npm run eval:business-dataset`: checks the generated 120-case business regression dataset shape and coverage.
- `npm run eval:business-import -- --input eval/business-regression.import.example.json`: validates a business regression import file. `--write` preserves the existing `items[]` shape and also emits `documents[]` + `queries[]` for `PROJECT_EVAL_DATASET`; each answerable item needs a source document with at least 80 characters of content. It carries through `synthetic` and `provenance` only when supplied; it never marks an import as real or reviewed automatically. Add `-- --input <path> --write --min-cases 100` only after the private dataset is sanitized. A release dataset must separately declare reviewed provenance, include at least 5 unique source documents, 100 unique queries, negative/conflict coverage, valid related document IDs, and expected claims. Keep private source data out of git.
- `npm run fixtures:private:prepare`: generates a synthetic fixture pack: 193 business regression questions, multimodal files, GraphRAG seed docs, and organization permission data. JSON outputs include synthetic provenance, and `eval/private-fixtures/manifest.json` identifies all generated files. These fixtures contain no real business data.
- `npm run fixtures:private:check`: validates the generated synthetic fixture pack, provenance metadata, manifest, and expected coverage.
- `npm run eval:business-private`: validates `eval/private-business-regression.dataset.json` with at least 50 cases.
- `npm run eval:rag:multimodal:private`: validates `eval/private-multimodal.dataset.json` in strict asset mode.
- `npm run graph:import-private`: dry-runs `eval/private-graph-business.seed.json`.

Backend service checks default to `http://localhost:3000`.
